Memcached stats conns Command Guide

The stats conns command in Memcached is a specialized diagnostic utility used to inspect real-time details of all currently open client connections. While high-level metrics provide overall connection counts, this command delivers granular, per-connection visibility into socket states, network addresses, and active client behaviors. System administrators and engineers rely on stats conns to troubleshoot connection leaks, diagnose network latency, identify rogue clients, and ensure client connection pools are operating efficiently.

Purpose and Functionality

When issued via the Memcached text protocol (typically through tools like Netcat or Telnet), stats conns iterates through the internal connection structures maintained by the Memcached daemon. Instead of aggregate numerical counters, it outputs the specific state of each active file descriptor assigned to a client.

Key information provided by the command includes:

  • File Descriptor (FD): The internal operating system handle assigned to the network socket, helping correlate Memcached connections with system-level socket utilities like lsof or netstat.
  • Client IP and Port: The remote network address of the connected client, allowing administrators to pinpoint which application servers or worker nodes are generating the traffic.
  • Connection State: The current operational phase of the connection within Memcached's event loop. Common states include:
    • conn_waiting: The socket is idle, waiting for the client to send a new request.
    • conn_read: Memcached is actively reading bytes from the socket.
    • conn_parse: The server is processing the received protocol commands.
    • conn_write: The server is actively sending cached responses back to the client.
  • Protocol and Transport: Whether the connection is operating over TCP or UDP, and if it is utilizing the standard text protocol or the binary protocol.

Practical Use Cases

Monitoring active client links via stats conns addresses several common production issues:

  1. Detecting Connection Leaks: If an application opens connections without properly closing them or returning them to a connection pool, the connection count continuously rises. Inspecting stats conns helps identify connections stuck in conn_waiting for extended periods, pinpointing the source application via the client IP.
  2. Identifying Slow or Blocking Clients: Sockets remaining in conn_read or conn_write can indicate client-side network bottlenecks, slow network links, or oversized payloads that are delaying the event loop.
  3. Validating Connection Pools: Application clusters utilizing connection pooling should maintain a steady, predictable distribution of open sockets. This command verifies whether pools are evenly distributed across the Memcached cluster or if a single instance is disproportionately loaded.
  4. Security and Unauthorized Access Auditing: The per-connection IP breakdown allows quick detection of unexpected or unauthorized IP addresses communicating with the Memcached service.
