How to Measure Memcached Eviction Rates

This article provides an overview of strategies software developers use to measure key eviction rates in production Memcached deployments. It covers native telemetry commands, time-series metrics collection, slab-level analysis, and alerting techniques necessary to detect memory pressure and maintain optimal cache performance.

Using Native Memcached Telemetry

Memcached provides built-in statistical counters accessible via the text or binary protocol. Developers can query these counters directly via tools like nc (netcat), telnet, or application-level socket clients.

  1. Global Eviction Counter (stats): Running the stats command returns the evictions metric, which represents the cumulative number of valid items removed from the cache before their expiration to make room for new writes. Because this is a monotonically increasing counter since server boot, a single snapshot is not sufficient to determine current behavior.
  2. Per-Slab Statistics (stats items): Memcached allocates memory using slab classes divided by item size. Querying stats items reveals eviction distribution across these classes via items:<slab_id>:evicted. This indicates precisely which item size brackets are experiencing memory shortages.
  3. Age-Based Metrics (evicted_time): Accessible in modern Memcached versions, evicted_time tracks the seconds since the last access of the most recently evicted item. If this number is extremely low, it indicates the cache is discarding recently used items (hot data).

Calculating Eviction Rate Over Time

Because Memcached only reports cumulative eviction totals, developers calculate the eviction rate mathematically over a specific time window (\(\Delta t\)):

\[\text{Eviction Rate} = \frac{\text{evictions}_{t_2} - \text{evictions}_{t_1}}{t_2 - t_1}\]

Measuring eviction rate as a per-second value (\(E/s\)) normalizes the metric, allowing developers to distinguish between normal baseline evictions and sudden traffic-driven spikes.

Integrating with Monitoring and Observability Systems

Manual command execution is insufficient for production. Engineering teams integrate Memcached metrics into time-series platforms:

  • Prometheus: Deploying the official memcached_exporter extracts native counters and exposes them as Prometheus metrics. The memcached_items_evicted_total counter can be monitored using PromQL functions like rate(memcached_items_evicted_total[5m]) to track real-time evictions per second.
  • Managed Cloud Metrics (AWS CloudWatch / GCP Cloud Monitoring): Managed solutions such as Amazon ElastiCache for Memcached expose a pre-calculated Evictions metric natively, reported at regular intervals (typically 1-minute resolution).
  • Datadog and APM Platforms: Agents like the Datadog Memcached check parse native stats automatically, mapping them to memcache.evictions.count and memcache.evictions.rate.

Correlating Eviction Rates with Other Indicators

Evaluating eviction rates in isolation can be misleading. To accurately diagnose cache health, developers correlate eviction rates with:

  • Hit Ratio: Calculated as get_hits / (get_hits + get_misses). A high eviction rate paired with a falling hit ratio confirms that working-set data is being evicted prematurely.
  • Bytes Used vs. Limit (bytes / limit_maxbytes): Evictions only occur when bytes approaches limit_maxbytes. Observing high evictions while total memory is low typically points to slab allocation imbalances rather than cluster-wide memory exhaustion.
  • Reclaimed Items (reclaimed): Items that expire naturally based on TTL and are subsequently overwritten. Comparing reclaimed against evictions shows whether keys are expiring naturally or being forced out.

Setting Alerting Thresholds

Production deployments require alerting rules based on eviction rate velocity rather than raw counts:

  • Rate-of-Change Alerts: Trigger warnings when rate(evictions) exceeds zero for sustained periods on slab classes handling critical application data.
  • Low Eviction Age Alerts: Alert if evicted_time drops below the expected cache lifetime or SLA (e.g., items being evicted within seconds or minutes of insertion).
  • Relative Drop in Hit Ratio: Alert when an increase in eviction rate coincides with a drop in global or service-level cache hit percentage.
