Memcached stats settings Command Guide

The stats settings command in Memcached outputs the active runtime configuration and internal operational flags of the server instance. Rather than displaying dynamic metrics like hit rates or item counts, this diagnostic command reveals the baseline parameters governing memory distribution, connection handling, thread management, and eviction logic. Analyzing these settings enables administrators to pinpoint whether performance bottlenecks, connection drops, or premature cache evictions stem from underlying workload characteristics or misaligned initialization flags.

Memory Allocation and Item Constraints

The command provides essential visibility into the memory boundaries established when the daemon started:

  • maxbytes: Displays the total maximum memory (in bytes) allocated to the Memcached instance. Comparing this value against real-time usage confirms whether the instance has adequate headroom.
  • item_size_max: Identifies the maximum permitted size for any single stored key-value pair (default is 1MB). This helps diagnose client-side errors caused by payloads that exceed the permitted ceiling.
  • chunk_size and growth_factor: Indicate the baseline chunk size and the multiplier applied across slab classes. These settings reveal how aggressively item sizes scale up, aiding in the diagnosis of slab allocation inefficiencies or memory fragmentation.

Network and Connection Configurations

Parameters under this category diagnose network-level boundaries and transport protocols:

  • maxconns: Specifies the maximum number of simultaneous client connections permitted. If clients face connection refused errors while CPU and memory are low, this threshold is often the limiting factor.
  • tcpport and udpport: Show the assigned network listening ports for TCP and UDP communication.
  • inter: Identifies the specific network interface IP address to which Memcached is bound, useful for verifying network isolation and listening interfaces.
  • backlog: Details the maximum size of the TCP listen queue for pending connections, critical for diagnosing connection drops during sudden traffic spikes.

Threading and System Concurrency

Multi-threading diagnostic values show how work is distributed across CPU cores:

  • num_threads: Displays the number of worker threads handling incoming client requests. A mismatch between thread count and available CPU cores can explain high latency or context-switching overhead under load.
  • reqs_per_event: Indicates the maximum number of requests a worker thread can process from a single connection before yielding to other connections, helping diagnose connection starvation issues.

LRU and Eviction Mechanisms

Cache replacement and memory recovery settings detail how Memcached handles full memory conditions:

  • evictions: Indicates whether item eviction is enabled (on or 1) when memory is exhausted, or disabled (0), which causes Memcached to return out-of-memory errors instead of discarding old keys.
  • lru_crawler: Shows whether the background thread that sweeps through LRU lists to clean up expired items is enabled.
  • lru_maintainer: Reports if the sub-LRU split management system (separating hot, warm, and cold data) is active, providing context when diagnosing why specific items are removed earlier than expected.
  • tail_repair_time: Shows the maximum time allowed to unjam locked slab buffers, helping detect issues with stranded references during evictions.

Security and Protocol Settings

  • auth_enabled_sasl: Indicates whether Simple Authentication and Security Layer (SASL) authentication is enforced on incoming client requests.
  • shutdown_command: Shows whether remote administrative shutdown signals are accepted over the network interface.
