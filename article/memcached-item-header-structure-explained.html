Memcached Item Header Structure Explained

Memcached manages memory by pairing every cached value with an internal metadata structure known as an item header. This article details the specific structural fields that make up the Memcached item header, explaining how this internal metadata facilitates memory allocation, LRU eviction, hash table lookups, and cache expiration.

The Item Structure (struct _stritem)

In the Memcached source code, an item header is defined as struct _stritem. This header precedes the actual key and data payload in memory. It tracks memory management, lifecycle, and concurrency details for each stored entry.

The primary structural elements stored in the item header include:

1. Linked List Pointers

  • next and prev: Pointers used to maintain doubly linked lists within the Least Recently Used (LRU) queues. These allow Memcached to quickly move items to the front of the queue upon access or identify stale items for eviction.
  • h_next: A pointer used for hash table collision resolution. Memcached uses separate chaining for its primary hash lookup table; h_next links to the next item sharing the same hash bucket.

2. Lifecycle and Timing Metadata

  • time: A 32-bit timestamp indicating the last time the item was fetched or updated. This is critical for evaluating LRU eviction priorities.
  • exptime: An expiration timestamp (either an absolute Unix epoch time or an offset in seconds). When a request queries an item whose exptime is in the past, Memcached treats it as expired and frees the memory.

3. Length and Dimension Specifiers

  • nbytes: The exact size of the item's data payload in bytes.
  • nkey: An 8-bit integer specifying the length of the cache key.
  • nsuffix: The length of the text suffix attached to the item, which holds the client-defined flags and the text representation of the payload length.

4. Memory and Concurrency Management

  • refcount: A reference counter that tracks how many active worker threads are reading or holding a reference to the item. An item cannot be freed or repurposed by the allocator until this counter drops to zero.
  • slabs_clsid: The ID of the slab class where the item is allocated. This defines the chunk size category assigned by the slab allocator.
  • it_flags: Bit flags representing internal states of the item, such as whether it is linked into the hash table (ITEM_LINKED), formatted as a CAS token, or stored in a specific LRU sub-queue.

5. Check-and-Set (CAS) Identifier

  • cas: A 64-bit unsigned integer that increments sequentially. It enables atomic Check-And-Set operations, allowing clients to avoid race conditions by updating a key only if its CAS value matches the one read initially.

Data Layout Directly Following the Header

Immediately following the fixed-size _stritem header in contiguous memory, Memcached stores:

  1. CAS (Optional padding): Space reserved for 64-bit alignment if CAS is enabled.
  2. Key: The actual string key used for lookups.
  3. Suffix: A short string containing binary/text protocol flags.
  4. Value: The binary payload of the cached object.
