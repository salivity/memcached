How to Increment Values Atomically in Memcached

This article explains how to atomically increment an integer value in Memcached to handle real-time counters safely without race conditions. You will learn the exact command used for atomic increments, its syntax and parameters, expected server responses, and critical behavioral constraints required to execute the operation successfully.

The Atomic Increment Command: incr

In Memcached, the command used to increment an integer value atomically is incr.

Atomicity guarantees that even if multiple clients attempt to modify the same counter simultaneously, each operation is processed sequentially without conflicting or overwriting concurrent updates. This eliminates the need for external locking mechanisms when tracking metrics such as page views, rate limits, or inventory counts.

Syntax

The protocol syntax for the incr command is:

incr <key> <value> [noreply]\r\n
  • <key>: The identifier of the item you want to increment.
  • <value>: The amount by which to increment the key's current value. This must be an unsigned 64-bit integer.
  • [noreply]: An optional parameter instructing the server not to send a response, reducing network round-trip overhead for high-throughput write operations.

Expected Responses

When the noreply flag is not specified, Memcached returns one of the following responses:

  • <new_value>\r\n: Indicates success. The server returns the updated numeric value of the key.
  • NOT_FOUND\r\n: Returned if the target key does not exist. Memcached will not automatically create a missing key when calling incr.
  • CLIENT_ERROR cannot increment or decrement non-numeric value\r\n: Returned if the stored data is not an ASCII representation of an integer.

Key Requirements and Constraints

  1. Pre-existing Key: Because incr does not initialize keys, the key must first be initialized using a storage command such as set or add.
  2. Data Format: The value must be stored as a string representation of a decimal integer (e.g., "10"). Binary-serialized integers or non-numeric strings will result in a client error.
  3. Integer Bounds and Overflow: Memcached counters are unsigned 64-bit integers ranging from 0 to 18,446,744,073,709,551,615. If an increment causes the value to exceed this upper limit, the counter wraps around to 0.
  4. No Negative Values: The incr command cannot accept negative values. To decrease a counter atomically, use the corresponding decr command.
