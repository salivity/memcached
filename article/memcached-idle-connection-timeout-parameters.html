Memcached Idle Connection Timeout Parameters

Managing connection lifecycles in Memcached is essential for preventing connection exhaustion and freeing up server resources. By default, Memcached allows idle client connections to remain open indefinitely. However, Memcached provides a specific command-line parameter, along with underlying operating system TCP controls, to configure automatic disconnection thresholds for inactive clients. This article explains the exact parameters governing Memcached idle connection timeouts and how to configure them effectively.

The Primary Setting: -o idle_timeout

The primary parameter controlling how long Memcached waits before closing an inactive connection is -o idle_timeout=<seconds>.

  • Default Value: 0 (disabled). Connections stay open until the client explicitly terminates the socket or the connection is severed by a network failure.

  • Functionality: When set to a positive integer, Memcached monitors how long each client connection remains inactive (no incoming commands). If no requests are received within the specified number of seconds, Memcached closes the connection.

  • Usage Example:

    memcached -m 1024 -p 11211 -o idle_timeout=60

    In this example, Memcached automatically terminates any client connection that remains idle for 60 seconds.

Verifying the Configuration

To check whether the idle timeout is enabled on a running instance, connect via Telnet or netcat and query the server settings:

echo "stats settings" | nc localhost 11211 | grep idle_timeout

The output will display the current value:

STAT idle_timeout 60

If the value is 0, idle connections will not be dropped automatically by the Memcached daemon.

Operating System and TCP Keepalive Controls

When -o idle_timeout is disabled, connection cleanup depends on operating-system-level TCP keepalive settings. If an idle client crashes, drops offline, or terminates improperly without sending a FIN or RST packet, the connection becomes orphaned.

The operating system handles these dead sockets using standard Linux kernel parameters:

  • net.ipv4.tcp_keepalive_time: The interval (in seconds) between the last data packet sent and the first keepalive probe.
  • net.ipv4.tcp_keepalive_intvl: The interval between subsequent keepalive probes if no response is received.
  • net.ipv4.tcp_keepalive_probes: The number of unacknowledged probes sent before declaring the connection dead and closing the socket.

To avoid lingering dead sockets when not using -o idle_timeout, administrators typically lower tcp_keepalive_time in /etc/sysctl.conf.

Interaction with Maximum Connections (-c)

Idle timeouts directly affect the connection limit set by the -c <num> parameter, which defaults to 1024 concurrent connections. When client applications maintain persistent connection pools without proper reuse or closure, the connection pool can quickly saturate. Setting -o idle_timeout ensures that abandoned connections are recycled before reaching the maximum connection limit, preventing connection limit reached errors.
