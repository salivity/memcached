Memcached TTL Over 30 Days: How Expiration Works

In Memcached, configuring a key's expiration time requires an understanding of how the server parses time-to-live (TTL) values. While values up to 30 days are treated as relative offsets in seconds, any integer exceeding 30 days is automatically interpreted as an absolute Unix epoch timestamp. This article explains the technical mechanics behind this threshold, why passing large relative values causes keys to expire immediately, and how to properly configure long-term caching.

The 30-Day Threshold Rule

Memcached uses a 32-bit integer for expiration times (exptime). To balance convenience and flexibility, the Memcached protocol defines a threshold of 2,592,000 seconds—the exact number of seconds in 30 days (60 seconds × 60 minutes × 24 hours × 30 days).

When an item is stored with an exptime:

  • Values from 1 to 2,592,000: Memcached treats the number as a relative offset. The item will expire that many seconds from the current server time.
  • Values of 0: The item never expires automatically (though it can still be evicted to free memory).
  • Values greater than 2,592,000: Memcached treats the number as an absolute Unix timestamp (seconds elapsed since January 1, 1970, 00:00:00 UTC).

The Immediate Expiration Trap

If an application attempts to set an item with a relative expiration of 40 days by passing 3,456,000 seconds (40 × 86,400), Memcached does not add 40 days to the current time. Because 3,456,000 is greater than 2,592,000, the server interprets 3,456,000 as the absolute timestamp:

February 9, 1970, 08:00:00 UTC

Because this timestamp is decades in the past relative to the current system clock, Memcached considers the item expired upon creation. The storage command may succeed, but any subsequent retrieval attempt returns a cache miss.

Correctly Handling Expirations Beyond 30 Days

To store an item for longer than 30 days, you must explicitly supply an absolute Unix timestamp rather than a relative offset. This is done by adding the desired duration to the current Unix time before sending the command to Memcached.

For example, to set an expiration of 60 days:

  1. Obtain the current Unix epoch time in seconds.
  2. Add the duration: current_timestamp + (60 * 86400).
  3. Pass the resulting sum as the exptime parameter.

Because this sum represents a future point in time well beyond the current year, it will vastly exceed 2,592,000, prompting Memcached to evaluate it as the intended absolute date and time.
