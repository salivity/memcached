How to Backup and Restore Memcached Data

Memcached is fundamentally an in-memory, volatile caching system designed without native data persistence, meaning all stored keys are lost when the service restarts. However, operational requirements—such as maintenance, node migrations, or cold-start prevention—often demand strategies to extract and reload this transient data. This article explores practical methods for backing up and restoring Memcached data, covering command-line extraction utilities, process-level snapshotting, application-layer warming patterns, and persistent proxy architectures.

1. Extracting Data with Native and Community Tools

Because Memcached stores data in memory slabs, you can inspect and dump active keys using native management protocols and client tools.

Using memcdump and Custom Fetch Scripts

The libmemcached-tools package provides memcdump, which connects to a running Memcached instance and outputs a list of all current keys:

memcdump --servers=127.0.0.1:11211 > memcached_keys.txt

Once the keys are extracted, a script (written in Python, Go, or Bash) can iterate through the list, perform a get command for each key, serialize the key-value pairs (along with their flags and TTLs) into a JSON or binary file, and write them to disk. To restore, the script simply iterates over the saved file and executes set or add commands against the target Memcached instance.

Note: In production environments with high key volumes, dumping all keys sequentially can degrade performance or cause temporary latency spikes.

Using memcached-tool

The Perl script memcached-tool, often packaged directly with Memcached, allows you to dump data directly using the slab dump feature:

memcached-tool 127.0.0.1:11211 dump > memcached_backup.txt

This utility dumps keys and values directly. You can restore this data by piping the generated set commands back into the Memcached port using nc (netcat):

nc 127.0.0.1 11211 < memcached_backup.txt

2. OS-Level Process Checkpointing (CRIU)

When you need an exact byte-for-byte state preservation without querying individual keys, you can leverage Checkpoint/Restore in Userspace (CRIU) on Linux.

  • Backup: CRIU freezes the running Memcached process and copies its entire memory space and socket states to disk files.
  • Restore: CRIU reconstructs the process state directly from those files, resuming execution with all in-memory keys intact.

This approach is particularly useful during scheduled host reboots or kernel upgrades, as it avoids cache cold-starts entirely without modifying application logic.

3. Application-Level Cache Warming

In standard distributed architectures, Memcached is treated as strictly ephemeral. Rather than taking physical backups of the cache, organizations implement automated cache warming pipelines.

  • Rebuilding from the Primary Datastore: If Memcached acts as a read-through or lookaside cache, a background worker can query the primary database (e.g., PostgreSQL, MySQL) for high-frequency records and repopulate Memcached before directing user traffic to the instance.
  • Access Log Replay: Web server access logs or streaming replication logs (e.g., via Apache Kafka) can be replayed against a fresh Memcached instance to pre-populate popular keys based on real-world traffic patterns.

4. Replicated Architectures and Routing Proxies

Instead of traditional point-in-time file backups, high availability setups prevent data loss during single-node failure by mirroring data across multiple nodes.

  • Mcrouter: Developed by Facebook, Mcrouter is a Memcached protocol router. It can be configured with prefix routing, replication, and "shadowing." By configuring Mcrouter to mirror writes to multiple distinct Memcached clusters, one cluster acts as a live backup of the other. If one instance fails or restarts, the secondary cluster supplies the data.
  • Persistent Protocols: If business requirements mandate continuous persistence, consider deploying a storage engine that speaks the Memcached ASCII/binary protocol but includes native disk persistence, such as KeyDB or Couchbase.
