Memcached Memory Limit Metrics in Stats

In Memcached, monitoring memory capacity is essential for maintaining application performance and preventing unexpected cache turnover. This article explains the key metrics in the stats output that reveal when Memcached has reached its memory allocation limit, focusing primarily on evictions, the relationship between bytes and limit_maxbytes, and the out_of_memory counter.

The Primary Metric: evictions

The most definitive metric indicating that Memcached has reached its memory allocation limit under default settings is evictions.

By default, Memcached operates as a Least Recently Used (LRU) cache. When the server reaches its configured memory limit (set by the -m flag) and needs to allocate space for a new item, it frees space by removing valid, non-expired items. Each time an item is removed to make room for new data, the evictions counter increments.

  • A value of evictions: 0 means Memcached has either not reached capacity or is successfully reusing memory from naturally expired items.
  • A continuously rising evictions count means the server has hit its memory limit and is actively purging active data to accommodate new writes.

Capacity Indicators: bytes vs. limit_maxbytes

To check how close Memcached is to its memory threshold before evictions occur, compare two specific values from the general stats command:

  • limit_maxbytes: The maximum amount of memory (in bytes) allowed for storage.
  • bytes: The current number of bytes used to store items.

When bytes approaches or equals limit_maxbytes, memory allocation limits have been reached, and Memcached will begin relying on either expiration or eviction to accept new records.

The Strict Limit Metric: out_of_memory

If Memcached is started with the -M flag, automatic LRU evictions are disabled. Under this configuration, reaching the memory ceiling behaves differently:

  • Instead of evicting items, the server rejects new set operations and throws a memory allocation error.
  • The out_of_memory metric will increment each time an item fails to write due to a lack of available memory.

Checking Slab-Specific Limits

Memcached divides memory into pre-allocated memory pools called slab classes. You can identify if a specific slab class has saturated its memory pool by running the stats slabs command. Look for:

  • evicted: The number of times an item was purged from that specific slab class.
  • outofmemory: The number of times that specific slab class could not allocate memory for a new item.
