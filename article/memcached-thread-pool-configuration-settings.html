Memcached Thread Pool Configuration Settings

Memcached uses a multithreaded architecture designed to scale read and write operations across multi-core processors. This article outlines the primary configuration flags used to size and balance Memcached's thread pool, detailing how the dispatcher assigns workloads to worker threads and which parameters prevent thread starvation and resource bottlenecks.

Worker Thread Pool Sizing (-t)

The primary configuration setting for controlling the size of the Memcached thread pool is the -t (or --threads) flag.

  • Flag: -t <number>
  • Default: 4
  • Function: Defines the number of worker threads dedicated to processing incoming read and write requests.

Memcached delegates network events using libevent. When requests arrive, a dedicated master thread (the dispatcher) accepts the connections and distributes them to these worker threads.

Sizing Recommendations:

  • Set -t to match the number of physical or logical CPU cores available on the system.
  • Avoid setting -t significantly higher than the core count, as excessive thread context switching creates unnecessary CPU overhead without increasing throughput.
  • Setting -t lower than the core count can lead to unutilized CPU capacity under heavy loads.

Workload Distribution and Fair Scheduling (-R)

Worker threads manage multiple client connections concurrently. To prevent a single high-traffic connection from monopolizing a worker thread and starving other connections, Memcached uses the -R parameter.

  • Flag: -R <number> (or -o max_reqs_per_event=<number>)
  • Default: 20
  • Function: Sets the maximum number of requests a worker thread will process for a single connection before yielding execution to handle events from other assigned connections.

Lowering this value improves fairness and reduces latency jitter across competing connections at the cost of slight scheduling overhead. Raising it increases batch processing efficiency for persistent, high-throughput connections.

Connection Limits and Distribution (-c)

While -c controls the global connection ceiling rather than thread counts directly, it dictates how many concurrent connections are distributed across the active thread pool.

  • Flag: -c <number> (or --conn-limit=<number>)
  • Default: 1024
  • Function: Sets the maximum simultaneous connections allowed.

Because the master thread assigns connections to worker threads in a round-robin manner, the ratio of -c to -t determines the maximum theoretical concurrency load per thread.

Dedicated Internal Maintenance Threads

In modern versions of Memcached, background tasks are isolated from the main worker thread pool to eliminate blocking operations. These maintenance threads are managed by specific feature flags:

  • Hash Table Expansion: Automatically spawns a dedicated maintenance thread when the primary hash table needs to resize.
  • LRU Crawler (-o lru_crawler): Runs on a background thread to inspect and invalidate expired items without blocking reads/writes.
  • Slab Reassigner (-o slab_reassign): Manages memory redistribution across slab classes via an independent background thread.

Applying Configuration Changes

To apply these thread settings, pass them via the command line when starting the daemon or add them to your environment configuration file:

  • Command Line:

    memcached -t 8 -R 50 -c 4096 -m 4096 -u memcached

  • Debian/Ubuntu (/etc/memcached.conf):

    -t 8
-R 50
-c 4096

  • RHEL/CentOS (/etc/sysconfig/memcached):

    OPTIONS="-t 8 -R 50"
MAXCONN="4096"

Restart the Memcached service after editing configuration files to apply the new thread pool and distribution parameters.
