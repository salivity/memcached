Memcached UDP Amplification DDoS Attacks Explained

In early 2018, cybercriminals leveraged exposed Memcached servers to launch some of the largest Distributed Denial of Service (DDoS) attacks in internet history, reaching peak volumes of 1.35 terabits per second. This article explains the primary security exposures that made these devastating attacks possible: enabled-by-default UDP support, a total lack of authentication, open internet exposure, and an unprecedented amplification factor.

Default UDP Listener Support

The foundational vulnerability behind the attack vector was Memcached's historical decision to enable UDP protocol support by default on port 11211. Unlike TCP, which requires a three-way handshake to establish a connection, UDP is a connectionless, stateless protocol. This inherent characteristic allows an attacker to easily forge (spoof) the source IP address in a packet header. By forging requests to appear as though they originated from the victim's IP address, the attacker redirected all responses straight to the victim.

Lack of Authentication Mechanisms

Memcached was originally conceived as an in-memory key-value store intended solely for private, trusted internal networks. Because of this core design philosophy, early versions possessed no default authentication mechanisms. Any client able to send packets to port 11211 could immediately execute commands, retrieve data, and request diagnostic information without validating identity or credentials.

Public Internet Exposure and Default Binding

Despite being built exclusively for internal network operations, tens of thousands of Memcached instances were deployed publicly on the internet. Default software configurations often bound the service to all available network interfaces (0.0.0.0) rather than restricting it to localhost (127.0.0.1) or a private local subnet. Additionally, missing perimeter firewall rules allowed public traffic to reach port 11211 unimpeded.

Extreme Amplification Factor

When combined, spoofed UDP packets and open access allowed attackers to weaponize Memcached's high throughput. A tiny request—such as a single 15-byte get or stats command—could cause the server to reply with thousands of response packets totaling hundreds of kilobytes or even megabytes of cached data. This produced an unprecedented amplification ratio of up to 51,200 to 1. Attackers could also deliberately prime servers by loading large payloads into cache before issuing the spoofed retrieval command, turning modest botnet bandwidth into overwhelming terabit-scale floods.

Mitigation and Long-Term Resolution

Following the 2018 incidents, the Memcached development team released version 1.5.6, which disabled the UDP protocol by default. Internet service providers, cloud platforms, and network administrators concurrently implemented strict firewall filtering on UDP port 11211, nullified spoofed traffic via BCP 38 anti-spoofing ingress filtering, and isolated exposed internal caching layers from the public internet.
