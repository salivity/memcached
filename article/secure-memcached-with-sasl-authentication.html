Secure Memcached with SASL Authentication

This guide provides a step-by-step walkthrough for securing a Memcached deployment using Simple Authentication and Security Layer (SASL). By enabling SASL, you can prevent unauthorized access and data tampering by requiring client authentication before executing cache commands. Below, you will find instructions for installing the necessary SASL dependencies, setting up user credentials, configuring the Memcached daemon with SASL support, and verifying your secured connection.

1. Install Required Packages

To enable SASL, your system requires the Cyrus SASL libraries and administrative utilities alongside the Memcached package. Most modern distributions provide Memcached precompiled with SASL support.

On Ubuntu or Debian systems:

sudo apt-get update
sudo apt-get install memcached sasl2-bin libsasl2-modules libsasl2-dev

On Rocky Linux, AlmaLinux, or RHEL:

sudo dnf install memcached cyrus-sasl cyrus-sasl-plain cyrus-sasl-devel

2. Configure the SASL Application File

Memcached looks for a SASL configuration file defining the authentication mechanisms and password checking methods. Create or edit /etc/sasl2/memcached.conf:

mech_list: plain
pwcheck_method: auxprop
auxprop_plugin: sasldb
sasldb_path: /etc/sasl2/memcached-sasldb
  • mech_list: plain specifies the authentication mechanism.
  • pwcheck_method: auxprop directs SASL to use an auxiliary property plugin for password lookups.
  • auxprop_plugin: sasldb specifies the SASL database backend.
  • sasldb_path points to the database file storing the user credentials.

3. Create Credentials in the SASL Database

Use saslpasswd2 to create the administrative or application credentials within the specified database.

Run the following command, replacing cacheuser with your desired username:

sudo saslpasswd2 -a memcached -c -f /etc/sasl2/memcached-sasldb cacheuser

You will be prompted to enter and confirm a password.

Next, set the correct ownership and file permissions so the Memcached daemon can read the database file:

# On Debian/Ubuntu:
sudo chown memcache:memcache /etc/sasl2/memcached-sasldb
sudo chmod 600 /etc/sasl2/memcached-sasldb

# On RHEL/Rocky Linux:
sudo chown memcached:memcached /etc/sasl2/memcached-sasldb
sudo chmod 600 /etc/sasl2/memcached-sasldb

4. Enable SASL in Memcached Configuration

To enforce authentication, pass the -S flag to the Memcached daemon.

On Debian/Ubuntu:

Edit /etc/memcached.conf and add the -S flag on a new line:

-S

On RHEL/CentOS:

Edit /etc/sysconfig/memcached and append -S to the OPTIONS variable:

OPTIONS="-S -l 127.0.0.1 -U 0"

After modifying the configuration, restart the Memcached service:

sudo systemctl restart memcached

Verify that the service is running with SASL enabled:

sudo systemctl status memcached

5. Verify the Authenticated Configuration

To confirm that unauthenticated access is blocked and authenticated access functions correctly, you can test the setup using Python and a SASL-compatible client library such as bmemcached.

Install the test client:

pip install python-binary-memcached

Run a simple script to verify:

import bmemcached

# Attempt to connect using credentials
client = bmemcached.Client(('127.0.0.1:11211',), 'cacheuser', 'your_password')

# Set and retrieve a key
client.set('test_key', 'SASL_Verified')
value = client.get('test_key')

print(f"Retrieved: {value}")

If the credentials are valid, the client returns the cached value. Requests made without valid SASL authentication will be rejected by the server, ensuring that only authorized applications can access or modify your Memcached data.
