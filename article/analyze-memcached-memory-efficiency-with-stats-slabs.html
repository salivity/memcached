Analyze Memcached Memory Efficiency with Stats Slabs

Memcached relies on a slab allocation mechanism to prevent memory fragmentation, dividing memory into predefined slab classes with fixed-size chunks. Analyzing the metrics provided by the stats slabs command allows developers to evaluate how efficiently memory is being allocated, identify internal fragmentation (slack space), and determine whether slab classes are appropriately matched to application payload sizes. This guide explains how to extract, compare, and interpret key slab metrics to optimize Memcached memory utilization.

Understanding the Memcached Slab Allocator

Memcached avoids operating system memory fragmentation by allocating memory in fixed 1 MB pages. Each page is divided into equal-sized chunks defined by slab classes. As item sizes grow, each subsequent slab class increases chunk capacity based on a growth factor (default is 1.25).

When a key-value pair is stored, Memcached places it into the smallest slab class that can fit the data. If the item does not completely fill the chunk, the remaining unused space inside that chunk cannot be used by other keys. This difference represents internal fragmentation, or "slack space."

Key stats slabs Metrics to Monitor

Issuing the stats slabs command via telnet or memcached-tool outputs metrics for each active slab class (indexed as [slab_id]:[metric]), as well as global summaries. The most critical per-slab metrics include:

  • chunk_size: The maximum byte size of an item that fits in this slab class.
  • chunks_per_page: The number of chunks allocated per 1 MB page.
  • total_pages: Total number of pages allocated to this slab class.
  • total_chunks: Total chunk capacity (total_pages * chunks_per_page).
  • used_chunks: The number of chunks currently storing data.
  • free_chunks: Available chunks inside already allocated pages (total_chunks - used_chunks).
  • mem_requested: Total bytes of actual data stored within this slab class.

Comparing Metrics to Evaluate Efficiency

Developers can evaluate efficiency across three primary dimensions: internal fragmentation, chunk saturation, and page distribution.

1. Calculating Internal Fragmentation (Slack Space)

Internal fragmentation occurs when stored payloads are significantly smaller than the slab's chunk_size.

To calculate the exact amount of wasted memory within currently stored items for a specific slab:

\[\text{Allocated Storage} = \text{used\_chunks} \times \text{chunk\_size}\] \[\text{Wasted Bytes} = \text{Allocated Storage} - \text{mem\_requested}\] \[\text{Efficiency Ratio} = \frac{\text{mem\_requested}}{\text{used\_chunks} \times \text{chunk\_size}}\]

An efficiency ratio close to 1.0 indicates optimal sizing. An efficiency ratio below 0.70 indicates that more than 30% of the memory assigned to stored items is being wasted as slack space.

2. Measuring Slab Capacity and Waste in Idle Chunks

Memcached permanently assigns 1 MB memory pages to a slab class once allocated. If items expire or are deleted, those chunks become idle.

To evaluate overall slab occupancy:

\[\text{Chunk Utilization Rate} = \frac{\text{used\_chunks}}{\text{total\_chunks}}\]

If a slab class has a high total_pages count but a consistently low Chunk Utilization Rate (and high free_chunks), memory has been captured by this slab class and cannot be reclaimed by other classes that might need it.

3. Identifying Slab Imbalance and Evictions

Correlate stats slabs with stats items to check for evictions. If one slab class shows high evictions while other slab classes exhibit high counts of free_chunks and low utilization, the cache is suffering from slab calcification or memory starvation in specific item size bands.

Optimization Strategies

If analysis reveals poor memory efficiency:

  • Tune the Growth Factor (-f): If the efficiency ratio is low across multiple slabs, decrease the growth factor (e.g., -f 1.1). This generates more slab classes with smaller size gaps, significantly reducing internal slack space at the cost of slight overhead.
  • Adjust Minimum Chunk Size (-n): If small keys are dominating lower slabs with high slack space, decrease the initial item space setting to better fit small payloads.
  • Enable Slab Reassignment (slab_reassign / slab_automove): Enable runtime slab reassignment to allow Memcached to transfer unused 1 MB pages from idle slab classes to classes experiencing evictions.
  • Normalize Payload Sizes: Group application cache values into consistent, predictable sizes that match specific slab boundaries.
