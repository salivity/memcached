Memcached Interface Binding Startup Parameters

Securing a Memcached instance requires controlling which network interfaces the daemon listens to upon startup. This article outlines the specific command-line parameters and configuration directives used to bind Memcached to designated IPv4 addresses, IPv6 addresses, or local UNIX domain sockets, ensuring your cache is not unintentionally exposed to unauthorized networks.

The Primary Listen Parameter: -l

The main parameter controlling interface binding in Memcached is the -l (listen) flag. When starting the Memcached daemon from the command line or via an init script, you specify the IP address or host to which the daemon should bind.

memcached -l <ip_address>

Binding to Localhost

To ensure Memcached accepts connections solely from the local machine:

memcached -l 127.0.0.1

Binding to a Specific Network Interface

To bind the service to an internal private network adapter, supply that adapter's specific IP:

memcached -l 192.168.1.50

Binding to Multiple Interfaces

Modern versions of Memcached allow binding to multiple interfaces simultaneously by separating the addresses with a comma (without spaces):

memcached -l 127.0.0.1,192.168.1.50

Binding to IPv6 Addresses

The -l parameter also accepts IPv6 addresses. To bind strictly to the IPv6 loopback interface:

memcached -l ::1

To listen on both IPv4 and IPv6 loopback addresses:

memcached -l 127.0.0.1,::1

Note: If -l is omitted entirely, older Memcached releases or unconfigured binaries may bind to INADDR_ANY (0.0.0.0), exposing the cache to all inbound traffic on the configured port. Always explicitly define the -l parameter.

Alternative: Binding to UNIX Domain Sockets (-s)

If client applications reside on the same physical host as the Memcached instance, you can bypass network interfaces entirely by binding to a UNIX domain socket. This eliminates network interface exposure completely.

The parameters controlling UNIX socket binding are:

  • -s <path>: Specifies the absolute path to the UNIX socket file to listen on. Network ports (TCP/UDP) are disabled when this option is used unless explicitly configured otherwise.
  • -a <mask>: Sets the octal file permissions for the socket file (defaults to 0700).

Example:

memcached -s /var/run/memcached/memcached.sock -a 0766

Supplementary Port Parameters

While -l dictates the address, port parameters define the specific communication channels on that interface:

  • -p <num>: Controls the TCP port binding (default: 11211). Setting -p 0 disables TCP.
  • -U <num>: Controls the UDP port binding (default: 0 in modern versions to mitigate amplification attacks, previously 11211). Setting -U 0 turns off UDP listening completely.

Defining Bind Addresses in Configuration Files

In production environments managed by systemd or init scripts, these parameters are typically set within configuration files rather than manual command invocations:

  • Debian/Ubuntu (/etc/memcached.conf): Add or modify the -l flag:

    -l 127.0.0.1

  • RHEL/CentOS (/etc/sysconfig/memcached): Set the OPTIONS variable:

    OPTIONS="-l 127.0.0.1"
