Memcached Total Get Commands Since Startup

This article explains how to identify the Memcached statistic that tracks the total number of retrieval requests processed by a server. It covers the specific metric name, how to access it through Memcached administrative commands, and how to use it in conjunction with other performance metrics to determine your cache hit ratio.

The Memcached statistic that indicates the total number of get commands executed since the server started is cmd_get.

Every time a client sends a retrieval request—regardless of whether the key exists in memory or not—Memcached increments the cmd_get counter. Because it is a cumulative metric, it continuously tracks all read attempts until the Memcached service is restarted or the counter reaches its maximum integer limit.

How to View cmd_get

You can inspect the cmd_get value by querying the general Memcached statistics via a TCP connection.

Using Netcat in a terminal:

echo "stats" | nc 127.0.0.1 11211 | grep cmd_get

Alternatively, you can connect via Telnet:

telnet 127.0.0.1 11211

Once connected, type stats and press Enter. Locate the line displaying STAT cmd_get:

STAT cmd_get 1542890

Analyzing cmd_get

The cmd_get metric is essential for calculating application cache efficiency. Memcached breaks down cmd_get into two outcomes:

  • get_hits: The number of times requested keys were found in the cache.
  • get_misses: The number of times requested keys were not found in the cache.

The sum of these two metrics equals the total get operations:

\[\text{cmd\_get} = \text{get\_hits} + \text{get\_misses}\]

To calculate your overall cache hit ratio, divide get_hits by cmd_get:

\[\text{Hit Ratio} = \frac{\text{get\_hits}}{\text{cmd\_get}}\]

Monitoring cmd_get alongside get_hits provides clear insight into read traffic volume and how effectively Memcached reduces load on your underlying database.
