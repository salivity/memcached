Tuning Linux Limits for High Memcached Connections

To scale Memcached to handle tens of thousands of concurrent connections, the underlying Linux operating system must be tuned beyond its default constraints. By default, Linux limits file descriptors, socket backlogs, and network memory to conservative thresholds. This guide outlines the specific operating system parameters—including file descriptors, TCP connection queues, port ranges, and buffer memory—that must be increased to eliminate connection bottlenecks and support high-concurrency Memcached workloads.

1. File Descriptor Limits (Open Files)

In Linux, every active network connection consumes a file descriptor (FD). Default limits typically cap open files at 1,024, causing connections to drop once this ceiling is reached.

System-Wide Limit

Set the maximum number of file descriptors the entire system can allocate by modifying /etc/sysctl.conf:

fs.file-max = 2097152

Apply the setting immediately using sysctl -p.

Process-Level Limit

Increase the limits for the user running Memcached (typically memcached) in /etc/security/limits.conf:

memcached soft nofile 65535
memcached hard nofile 65535

If Memcached is managed by systemd, override the service unit by running systemctl edit memcached and adding:

[Service]
LimitNOFILE=65535

Ensure Memcached is also launched with the -c 65535 flag to instruct the daemon itself to accept that many connections.

2. TCP Backlog and Listen Queue Limits

When thousands of clients connect simultaneously, connection requests can fill up the listen queue, resulting in connection timeouts or dropped SYN packets.

Update the following settings in /etc/sysctl.conf:

  • net.core.somaxconn: Controls the maximum queue length for completely established sockets waiting to be accepted. Default is often 128 or 4,096. Increase to:

    net.core.somaxconn = 65535

  • net.ipv4.tcp_max_syn_backlog: Controls the queue size for half-open connections (SYN received, but ACK not yet received). Increase to:

    net.ipv4.tcp_max_syn_backlog = 65535

  • net.core.netdev_max_backlog: Determines the maximum number of packets queued on the input side when the interface receives packets faster than the kernel can process them.

    net.core.netdev_max_backlog = 10000

Additionally, start the Memcached daemon with the -b 65535 parameter to match the application listen backlog to the kernel queue.

3. Ephemeral Port Range and Connection Recycling

If the host runs intermediate proxies or client processes that connect and disconnect rapidly, local port exhaustion can occur.

In /etc/sysctl.conf, expand the ephemeral port range and enable TCP socket reuse:

# Expand the port range available for outgoing connections
net.ipv4.ip_local_port_range = 1024 65535

# Allow reuse of TIME_WAIT sockets for new connections
net.ipv4.tcp_tw_reuse = 1

# Reduce the time sockets stay in the TIME_WAIT state (default: 60)
net.ipv4.tcp_fin_timeout = 15

4. TCP Socket Buffers and Memory Allocation

Tens of thousands of open connections consume significant kernel memory for read and write buffers. Sizing these correctly prevents out-of-memory errors while preserving network throughput.

Add the following to /etc/sysctl.conf:

# Maximum socket receive and send buffer size
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216

# Minimum, default, and maximum TCP read buffers (bytes)
net.ipv4.tcp_rmem = 4096 87380 16777216

# Minimum, default, and maximum TCP write buffers (bytes)
net.ipv4.tcp_wmem = 4096 65536 16777216

# System-wide TCP memory thresholds (units are in pages, typically 4KB)
# [min, pressure, max]
net.ipv4.tcp_mem = 786432 1048576 1572864

Using lower minimum and default buffer sizes ensures the kernel does not over-allocate RAM for idle or lightweight connections, leaving sufficient memory for Memcached's primary key-value store.

5. Connection Tracking (Netfilter)

If the server uses iptables, nftables, or a firewall that loads the nf_conntrack module, every connection is tracked in memory. When the conntrack table fills up, incoming packets are dropped.

Increase the connection tracking table and reduce timeout values in /etc/sysctl.conf:

net.netfilter.nf_conntrack_max = 1048576
net.netfilter.nf_conntrack_tcp_timeout_established = 600

Where possible in high-throughput production environments, bypass connection tracking entirely for the Memcached port using the NOTRACK (raw table) target in your firewall rules.
