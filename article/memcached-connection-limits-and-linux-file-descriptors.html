Memcached Connection Limits and Linux File Descriptors

Memcached handles high-concurrency caching by pairing configurable application-level connection thresholds with Linux socket file descriptor management. Because every active network connection in Linux consumes a file descriptor, Memcached must coordinate its internal worker threads, the event-driven network loop, and operating system limits to accept, maintain, and terminate client connections efficiently. This guide explains how Memcached manages these connections, reacts when thresholds are reached, and interfaces with Linux kernel resource controls.

The Connection Limit Architecture (-c)

Memcached controls maximum simultaneous client connections using the -c startup parameter. By default, this limit is set to 1,024 connections.

Internally, Memcached uses libevent alongside an event loop (epoll on modern Linux systems) to manage non-blocking I/O across worker threads. Incoming connections are initially received by a main listening thread and subsequently distributed across worker threads via a round-robin mechanism. Each active client socket requires an independent file descriptor (FD).

Automatic File Descriptor Allocation and setrlimit

When Memcached initializes, it calculates the total number of file descriptors required to run reliably. This calculation includes:

  1. The maximum connection limit set by -c.
  2. Internal descriptors required for listening sockets (TCP and UDP).
  3. Inter-thread communication pipes.
  4. Logging, storage, or internal monitoring endpoints.

Memcached automatically attempts to raise its own file descriptor limit by invoking the setrlimit() system call with RLIMIT_NOFILE. It attempts to set the soft limit equal to the hard limit or high enough to accommodate the calculated descriptor requirement. If the process has insufficient privileges (such as running as an unprivileged user without elevated CAP_SYS_RESOURCE capabilities) and the system-enforced limit is lower than the configured -c value, Memcached logs a warning or fails to start.

Behavior When Connection Limits Are Reached

When active connections hit the configured -c limit, Memcached does not crash or abruptly terminate existing sessions. Instead, it engages protective backpressure mechanisms:

  • Disabling the Listener: Memcached temporarily stops listening for new connections by removing the listening socket from the libevent notification pool.
  • Tracking Rejections: The internal metric listen_disabled_num increments each time the listener is paused due to saturation.
  • TCP Backlog Queueing: While the listener is paused, incoming SYN packets accumulate in the Linux kernel's TCP listen backlog (somaxconn). If this backlog fills, clients experience connection timeouts or ECONNREFUSED errors.
  • Automatic Recovery: As soon as an active client disconnects and an FD is released, Memcached re-registers the listening socket with libevent and resumes accepting new client handshakes.

Linux Kernel and System-Level Limits

Even if Memcached is configured with a high -c value, underlying Linux limits can restrict capacity if not aligned:

  1. Process Limits (nofile): Set via /etc/security/limits.conf or in a systemd unit file using LimitNOFILE=65535. If systemd launches Memcached, it ignores PAM limits in limits.conf, making the unit file configuration mandatory.
  2. System-Wide Limits (fs.file-max): The maximum number of open file descriptors allowed across the entire operating system, configured via sysctl fs.file-max.
  3. TCP Backlog (net.core.somaxconn): Determines the length of the listen queue for pending requests. Memcached exposes the -b flag to set its backlog parameter, which must not exceed the kernel's net.core.somaxconn setting.

Monitoring and Verifying Limits

To verify that connection handling and file descriptors are functioning properly on a running instance:

  • Inspect Running Process Limits: Check /proc/<memcached_pid>/limits to confirm the Max open files soft and hard limits correspond to system expectations.
  • Inspect Open Sockets: Count current open file descriptors with ls -1 /proc/<memcached_pid>/fd | wc -l.
  • Query Memcached Telemetry: Connect via telnet or nc and issue the stats command to review key connection counters:
    • curr_connections: Currently open connections.
    • total_connections: Total connections handled since startup.
    • maxconns: Configured limit matching -c.
    • listen_disabled_num: Count of instances connection capacity was exhausted.
