Memcached Eviction When All Keys Are Unexpired

When Memcached reaches its memory limit and receives a new item, it frees space by running its Least Recently Used (LRU) eviction process within the specific slab class required by the new item. Even if every entry stored across all slab classes has an active, unexpired Time-To-Live (TTL), Memcached will forcibly evict the least recently accessed valid items rather than reject the incoming write, unless specifically configured to return an error.

Slab Allocation and Eviction Scope

Memcached allocates memory using a slab allocator, dividing total memory into 1MB pages assigned to different slab classes based on item size. Memory is not dynamically pooled as a single global block during runtime.

When a write operation arrives:

  1. Memcached identifies the appropriate slab class matching the item's byte size.
  2. If the slab class has free chunks or if total server memory has room to allocate a new 1MB page to this slab class, it stores the item without eviction.
  3. If the slab class is entirely full and the global memory ceiling is reached, Memcached restricts its search for space strictly to that specific slab class. It will not evict unexpired keys from other slab classes to make room, even if those other classes contain older data.

The Segmented LRU Workflow

Modern versions of Memcached use a Segmented LRU architecture to manage keys, splitting items into different queues: HOT, WARM, and COLD.

When an eviction must occur among unexpired entries:

  • Targeting the COLD Queue: Items naturally migrate from HOT or WARM down to the COLD queue as they remain unread. Evictions exclusively target the tail of the COLD LRU.
  • Overriding TTL: Expiration timestamps are ignored during eviction. The oldest item at the tail of the COLD queue is freed, its memory is reclaimed for the incoming key, and the internal evictions counter is incremented.
  • Slab Automove: If slab automove (-o slab_automove) is enabled, background threads monitor eviction rates. If a slab class constantly evicts active items while another slab class holds idle pages, Memcached attempts to reassign entire pages between classes. However, this is a background optimization; immediate writes still evict from the local slab class tail if no free chunk exists.

The -M Flag Exception

The standard behavior of evicting unexpired keys can be disabled using the -M runtime flag (or -o modern,no_lru_crawler).

When Memcached runs with the -M flag:

  • Automatic eviction of unexpired keys is disabled.
  • If a slab class is full, memory is exhausted, and no expired items exist to clean up, Memcached refuses the write operation.
  • The server returns an out-of-memory error (SERVER_ERROR out of memory storing object) to the client.

Monitoring Evictions of Valid Keys

To detect whether active, unexpired keys are being dropped, examine Memcached runtime statistics using the stats command:

  • evictions: Tracks the cumulative number of valid, unexpired items removed to make space for new writes.
  • reclaimed: Shows how often an expired item was found and reused before needing to trigger a forced eviction.
  • crawler_reclaimed: Shows background cleanup of expired items by the LRU crawler.

A steadily rising evictions count alongside zero or low numbers of expired keys confirms that the memory allocated to your slab classes is insufficient for your working set size.
