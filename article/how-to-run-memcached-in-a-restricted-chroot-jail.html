How to Run Memcached in a Restricted Chroot Jail

Running Memcached inside a chroot jail isolates the in-memory caching service to a designated directory tree, drastically limiting filesystem access in the event of an exploit. This guide provides a straightforward process for system administrators to prepare an isolated environment, populate necessary libraries and devices, configure network binding, and execute the Memcached process securely within the restricted jail.

1. Create a Dedicated User and Jail Directory

Isolating a daemon requires non-root execution and a dedicated directory hierarchy. Create an unprivileged user and group for Memcached, followed by the target chroot directory structure:

# Create dedicated user without a login shell
sudo groupadd -r memcache
sudo useradd -r -g memcache -d /var/jail/memcached -s /sbin/nologin memcache

# Build the directory tree
sudo mkdir -p /var/jail/memcached/{bin,dev,etc,lib,lib64,run}

2. Copy the Memcached Binary and Dependencies

A chroot environment lacks access to the system root, meaning all shared libraries required by the binary must exist inside the jail.

First, copy the memcached binary:

sudo cp /usr/bin/memcached /var/jail/memcached/bin/

Identify the required shared libraries using ldd:

ldd /usr/bin/memcached

Copy each library path listed in the output into the corresponding directory within the jail. For automated deployment, use this loop:

for lib in $(ldd /usr/bin/memcached | grep -o '/lib[^ ]*'); do
    sudo mkdir -p /var/jail/memcached$(dirname "$lib")
    sudo cp -v "$lib" /var/jail/memcached"$lib"
done

If your architecture separates dynamic linkers (such as /lib64/ld-linux-x86-64.so.2), ensure it is present within /var/jail/memcached/lib64/.

3. Populate Minimal System Files and Devices

Memcached requires certain minimal configuration files and device nodes, particularly for entropy, logging, and user resolution:

# Create standard device nodes
sudo mknod -m 666 /var/jail/memcached/dev/null c 1 3
sudo mknod -m 666 /var/jail/memcached/dev/urandom c 1 9
sudo mknod -m 666 /var/jail/memcached/dev/zero c 1 5

# Provide minimal user and group resolution
grep -E '^memcache:' /etc/passwd | sudo tee /var/jail/memcached/etc/passwd
grep -E '^memcache:' /etc/group | sudo tee /var/jail/memcached/etc/group

Ensure the runtime user owns the jail directories that require write access:

sudo chown -R memcache:memcache /var/jail/memcached/run

4. Test the Chroot Jail Manually

Before automating the service, verify that the application starts inside the jail using the chroot command:

sudo chroot /var/jail/memcached /bin/memcached -u memcache -m 64 -p 11211 -l 127.0.0.1 -vv

If it successfully binds and accepts connections without library-missing errors, stop the manual execution with Ctrl+C.

5. Automate Execution with Systemd

Create a custom systemd service or an override to run Memcached within the jail automatically on boot.

Create /etc/systemd/system/memcached-jail.service:

[Unit]
Description=Memcached in Chroot Jail
After=network.target

[Service]
Type=simple
User=root
ExecStart=/usr/sbin/chroot /var/jail/memcached /bin/memcached -u memcache -m 64 -p 11211 -l 127.0.0.1
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target

Reload systemd, enable, and start the new service:

sudo systemctl daemon-reload
sudo systemctl enable --now memcached-jail.service

6. Verify Isolation

Verify that the process is running and confined:

ps aux | grep memcached
ls -l /proc/$(pgrep -f "/bin/memcached")/root

The output of the /proc/<PID>/root symbolic link should point directly to /var/jail/memcached, confirming the process has no visibility above its designated root directory.
