Top Memcached Stats for Network I/O Performance

This article provides an overview of the key metrics generated by Memcached that allow engineers to monitor, measure, and optimize network I/O throughput performance. By issuing the standard stats command, Memcached reports several critical counters and gauges that reveal bandwidth utilization, traffic volume, and network concurrency bottlenecks. Understanding these specific statistics is vital for identifying network saturation, tracking ingress and egress trends, and ensuring low-latency data delivery.

Primary Bandwidth Metrics: bytes_read and bytes_written

The most direct indicators of network I/O throughput in Memcached are bytes_read and bytes_written.

  • bytes_read: The total cumulative number of bytes read by the server from the network. This represents the total ingress traffic, including client requests, keys, and values sent during write operations (SET, ADD, REPLACE).
  • bytes_written: The total cumulative number of bytes sent by the server back to the network. This represents total egress traffic, consisting of status responses, protocol overhead, and the serialized data payloads returned during read operations (GET, MGET).

Because these are cumulative counters, calculate throughput by taking the rate of change over time (delta bytes / delta time). Tracking these rates highlights network capacity consumption and reveals whether the network interface is approaching its physical bandwidth limits.

Request Rate and Protocol Throughput: Command Counters

Network I/O is driven not just by payload size, but by the frequency of packets and commands processed over the wire.

  • cmd_get: Total read requests received. In read-heavy workloads, spikes in cmd_get directly correlate with high egress bandwidth (bytes_written).
  • cmd_set: Total storage requests received. Spikes in cmd_set correspond with high ingress bandwidth (bytes_read).
  • get_hits vs. get_misses: A high hit ratio typically maximizes egress payload delivery, whereas a sudden drop in hit ratio reduces outbound throughput per request, revealing changes in packet-level network efficiency.

Network Concurrency and Capacity Metrics

Throughput is heavily influenced by how effectively Memcached handles incoming and active network sockets.

  • curr_connections: The current number of open client connections. A rapid spike can lead to socket exhaustion, thread contention, and reduced aggregate I/O throughput.
  • conn_yields: The cumulative count of times a connection yielded to allow another connection to process work. When Memcached hits its batch limit (defined by the -R parameter), it yields the event loop to prevent a single busy connection from starving others. A high or rapidly increasing conn_yields value indicates intense concurrent network activity and potential I/O queuing.
  • listen_disabled_num: Increments when the server hits its maximum connection limit (maxconns) and temporarily stops accepting new network connections. Any value above zero signals severe network backpressure and dropped or delayed client requests.

Derived Throughput Calculations

To translate raw Memcached statistics into actionable performance insights:

  1. Egress Bandwidth: Calculate (Δ bytes_written * 8) / Δ seconds to determine outbound throughput in bits per second (bps).
  2. Ingress Bandwidth: Calculate (Δ bytes_read * 8) / Δ seconds to determine inbound throughput in bits per second (bps).
  3. Average Response Size: Divide Δ bytes_written by Δ get_hits to determine the average payload size returned per read request, helping identify large key anomalies that might saturate network links.
