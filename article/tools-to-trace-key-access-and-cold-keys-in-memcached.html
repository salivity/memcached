Tools to Trace Key Access and Cold Keys in Memcached

Memcached is a high-performance, distributed memory caching system designed to speed up dynamic web applications by alleviating database load. Over time, unused or infrequently accessed items—known as "cold keys"—can consume valuable memory slabs, leading to premature evictions of active data. This article outlines the built-in utilities, open-source network sniffers, and kernel-level tracing tools developers use to trace key access patterns and pinpoint cold keys in Memcached.

Built-in Memcached Features

LRU Crawler

Modern versions of Memcached include an asynchronous background thread called the LRU Crawler. It inspects items in memory without blocking active operations.

  • lru_crawler metadump: This command dumps metadata (such as key name, expiration time, size, and last access time in seconds since the Unix epoch) for keys stored in the cache. By comparing the last-accessed timestamp with the current time, developers can identify keys that have not been requested over extended periods.
  • lru_crawler crawl: Triggers targeted inspections across specific slab classes to evaluate memory usage and stale data without full service interruption.

Slab and Item Statistics

Memcached provides native telemetry through its text protocol:

  • stats items: Displays allocation, eviction, and crawler metrics across slab classes, helping determine whether specific slabs are experiencing high eviction rates due to stagnant memory.
  • stats cachedump: A legacy debugging command that inspects keys within a specific slab class. While useful in isolated test environments, it locks the cache during execution and should be avoided in production environments with high throughput.

Network Traffic and Packet Analysis Tools

Because Memcached does not log every command natively to maintain sub-millisecond latency, network-level inspection is a popular method to observe live key access.

mctop

Inspired by top, mctop captures live traffic sent to Memcached via libpcap. It sniffs network interfaces, parses the Memcached protocol (both ASCII and binary), and aggregates real-time metrics. Developers can view request rates, bandwidth consumption, and hit/miss ratios per key. Cold keys are recognized by filtering out active patterns or analyzing items that appear in memory dumps but never register traffic in mctop.

McSnooper

McSnooper is another passive packet-capturing utility specifically built for Memcached traffic. It tracks get, set, and delete commands, allowing teams to log key frequency to external storage (like Elasticsearch or local disk) for batch analysis and access-frequency modeling.

tcpdump and Wireshark

For targeted debugging without installing third-party binaries on servers, standard network utilities suffice:

  • Use tcpdump on port 11211 to record raw packets to a .pcap file.
  • Open the capture in Wireshark, which features a native Memcached protocol dissector capable of filtering by specific commands (e.g., memcache.command == 0x00 for binary Get).

Kernel Tracing: eBPF and bpftrace

For zero-overhead profiling in production environments, Extended Berkeley Packet Filter (eBPF) tools provide visibility into Memcached socket operations or user-space tracepoints.

  • bpftrace scripts: Developers can attach probes to read and write syscalls on the Memcached process, extracting the raw command payloads. This allows programmatic tracking of access counts per key directly in kernel space before sending summaries to user space, eliminating the performance penalties associated with heavy packet capturing.

Application-Level Tracing

When infrastructure access is restricted, application-level monitoring serves as a reliable alternative:

  • APM and Metrics Libraries: Client wrappers (such as those in Python, Go, or Java) can emit metrics to Prometheus, Datadog, or StatsD on cache operations. Tagging metrics with key prefixes allows developers to map key usage frequency and detect obsolete cache key namespaces that are no longer requested by application code.
