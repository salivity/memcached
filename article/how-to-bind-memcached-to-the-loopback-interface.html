How to Bind Memcached to the Loopback Interface

By default, an improperly secured Memcached instance may expose caching services to the public internet, making it vulnerable to unauthorized data inspection and distributed denial-of-service (DDoS) amplification attacks. Configuring Memcached to listen exclusively on the local loopback interface (127.0.0.1 for IPv4 or ::1 for IPv6) ensures that only applications hosted on the same physical or virtual server can interact with the cache. This guide outlines the necessary configuration file edits and service restart commands across major Linux distributions to lock down Memcached.

1. Locate the Configuration File

The path to the Memcached configuration file depends on your operating system:

  • Debian / Ubuntu: /etc/memcached.conf
  • RHEL / CentOS / Rocky Linux / AlmaLinux: /etc/sysconfig/memcached

2. Update the Listen IP Address

Open the appropriate configuration file in a text editor with administrative privileges.

On Debian / Ubuntu

Open the file:

sudo nano /etc/memcached.conf

Find the -l parameter. By default, it may already be set to 127.0.0.1. If it is commented out, missing, or set to 0.0.0.0, update it as follows:

-l 127.0.0.1

To support both IPv4 and IPv6 loopback interfaces simultaneously, specify both separated by a comma:

-l 127.0.0.1,::1

Save and exit the file.

On RHEL / CentOS / Fedora

Open the file:

sudo nano /etc/sysconfig/memcached

Locate the OPTIONS parameter and set the IP address using the -l flag:

OPTIONS="-l 127.0.0.1"

Save and exit the file.

3. Disable the UDP Listener (Recommended)

To fully mitigate UDP-based amplification attacks, disable UDP listening by ensuring port 0 is passed to the -U parameter.

  • On Debian/Ubuntu, add or uncomment:

    -U 0

  • On RHEL-based systems, append -U 0 to the OPTIONS string:

    OPTIONS="-l 127.0.0.1 -U 0"

4. Restart the Memcached Service

Apply the changes by restarting the Memcached daemon:

sudo systemctl restart memcached

5. Verify the Binding

Verify that Memcached is listening only on the loopback interface using ss or netstat:

sudo ss -tlpn | grep memcached

The output should confirm that the service is bound strictly to 127.0.0.1:11211 (and [::1]:11211 if IPv6 was configured), rather than 0.0.0.0:11211 or *:11211:

LISTEN 0      1024   127.0.0.1:11211   0.0.0.0:*    users:(("memcached",pid=1234,fd=26))
