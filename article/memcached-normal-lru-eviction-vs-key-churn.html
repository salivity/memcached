Memcached: Normal LRU Eviction vs Key Churn

Distinguishing between healthy cache recycling and pathological key churn in Memcached is critical for maintaining application throughput and predictable database loads. While both conditions cause item evictions once memory reaches capacity, normal Least Recently Used (LRU) evictions discard long-dormant items to maintain a stable working set, whereas rapid key churn prematurely pushes out frequently read data. Monitoring tools differentiate between these states by analyzing age-at-eviction metrics, cache hit ratios, write-to-read ratios, and slab-specific allocation trends.

Analyzing Eviction Age (Age of Evicted Items)

The primary metric for diagnosing eviction health is the age of items at the moment they are purged. Modern versions of Memcached provide slab-level metrics and an LRU crawler that track the time elapsed between an item's creation or last access and its eviction.

  • Normal Eviction: The evicted items exhibit high age values. They have lived in the cache for extended periods without read requests, indicating the cache successfully held the data throughout its active lifecycle.
  • Rapid Key Churn: The eviction age drops significantly, sometimes down to seconds or milliseconds. When newly allocated items immediately force out recently written or read items, it signals that the cache capacity is insufficient for the current ingestion rate or that an influx of low-value, unique keys is displacing the active working set.

Evaluating Hit Ratio Degradation

Tracking eviction rates in isolation is misleading because a high eviction rate can occur during normal heavy traffic. Monitoring tools correlate evictions with the cache hit ratio (get_hits divided by total cmd_get).

  • Normal Eviction: The hit ratio remains high and stable. Evictions occur, but the active working set resides safely in memory, so application read requests continue to resolve successfully.
  • Rapid Key Churn: The hit ratio drops steeply in tandem with rising evictions. Because the churn evicts items before downstream services can read them, subsequent queries result in cache misses, generating increased query pressure on primary databases.

Tracking the Set-to-Get Ratio

Key churn is primarily driven by write-heavy anomalies, such as improper key generation, runaway background jobs, or missing TTL (Time-To-Live) configurations. Monitoring tools monitor the relationship between writes (cmd_set) and reads (cmd_get).

  • Normal Eviction: Read commands substantially outnumber write commands, maintaining the standard read-heavy profile typical of caching layers.
  • Rapid Key Churn: The rate of cmd_set surges relative to cmd_get. A set-to-get ratio approaching or exceeding 1:1 during high eviction periods indicates data is being written faster than it can be consumed, a classic hallmark of churn.

Slab Class Isolation

Memcached divides memory into slab classes based on item size. A global view can obscure churn if it is isolated to an individual key payload size.

Monitoring tools inspect stats slabs to evaluate eviction metrics per slab class:

  • If evictions and low eviction ages are localized to a single slab class, an application component is likely writing oversized or uniquely patterned keys in that specific byte range.
  • If evictions are uniform across all slab classes while eviction ages remain high, the instance is experiencing balanced memory utilization under normal operational growth.

Monitoring Reclaimed and Expired Unfetched Counters

Memcached tracks whether an item was ever retrieved before it expired or was evicted (expired_unfetched).

A sudden increase in expired_unfetched or items evicted without ever receiving a hit demonstrates that the application is populating the cache with disposable, zero-utility keys. When paired with high eviction counts, this confirms that the churn is actively displacing valuable data with unused payloads.
