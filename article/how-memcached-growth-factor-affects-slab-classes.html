How Memcached Growth Factor Affects Slab Classes

Memcached utilizes a slab allocation mechanism to manage memory and prevent fragmentation, grouping stored objects into predefined chunk sizes known as slab classes. The slab class growth factor—configured via the -f flag—serves as the multiplier that determines the rate at which chunk sizes increase from one class to the next. By adjusting this geometric multiplier, administrators directly control the total number of slab classes generated between the base item size and the maximum item size limit.

The Mathematical Relationship

Memcached generates slab classes sequentially. It begins at a base chunk size (typically 48 or 96 bytes) and increases each subsequent class by multiplying the previous size by the growth factor:

\[\text{Chunk Size}_{n} = \text{Chunk Size}_{n-1} \times f\]

This progression continues until the chunk size reaches the maximum allowable item size (by default, 1 megabyte). Because the starting point and the upper boundary remain constant, the growth factor controls the step size of the sequence. Consequently, the growth factor and the total count of created slab classes share an inverse relationship.

Impact of a Smaller Growth Factor

Lowering the growth factor (for example, reducing the default 1.25 to 1.08 or 1.1) reduces the gap between neighboring chunk sizes. Because each step increases by a smaller percentage, Memcached requires more iterations to bridge the gap from the minimum chunk size to the maximum item size.

  • Increases Total Slab Classes: More intermediate classes are created across the memory spectrum.
  • Reduces Internal Fragmentation: Data items fit closer to their ideal chunk size, reducing unused padding within chunks.
  • Risk of Ceiling Limits: Memcached enforces a compile-time ceiling on the total number of slab classes (historically defined as MAX_NUMBER_OF_SLAB_CLASSES, typically set to 63 or 200 depending on the version). If the growth factor is too small, Memcached may hit this maximum cap before chunk sizes can scale up to the maximum item size, causing large items to fail to store.

Impact of a Larger Growth Factor

Increasing the growth factor (for example, raising it from 1.25 to 1.5 or 2.0) causes chunk sizes to scale rapidly. Fewer steps are needed to reach the maximum item size.

  • Decreases Total Slab Classes: Memcached creates fewer, wider-spaced slab classes.
  • Increases Internal Fragmentation: Items with sizes falling between widely spaced classes are forced into significantly larger chunks, resulting in wasted memory per allocated object.
  • Broad Memory Distribution: A smaller pool of classes concentrates available memory pages into fewer buckets, which can help workloads that have highly erratic, non-uniform key-value sizes.

In summary, the growth factor alters the total number of slab classes by changing the granularity of memory chunk intervals: lower values increase the number of classes for tighter memory fitting, while higher values reduce the number of classes at the cost of higher per-item memory waste.
