How to Inspect Memcached Keys with stats cachedump

The stats cachedump command in Memcached provides administrators with a direct method to view and inspect individual keys stored within specific memory slabs. This guide explains how to connect to a Memcached instance, discover active slab IDs using the stats items command, execute stats cachedump to extract key names along with their metadata, and address the operational limitations of using this diagnostic tool in production environments.

Connecting to Memcached

To run administrative commands, connect to the Memcached service using a TCP utility such as telnet or nc (Netcat) on the default port 11211:

telnet 127.0.0.1 11211

Alternatively, you can pipe commands through Netcat:

nc 127.0.0.1 11211

Step 1: Identify Slab IDs with stats items

Memcached does not store all keys in a single global list; instead, it groups items of similar sizes into slabs. You must specify a slab class ID to dump its keys. Run the stats items command to view all active slabs containing items:

stats items

The output will contain lines structured like this:

STAT items:1:number 15
STAT items:1:age 240
STAT items:2:number 8
...
END

The integer immediately following items: is the slab class ID. In the example above, slab classes 1 and 2 contain cached items.

Step 2: Execute stats cachedump

Once you have identified the target slab ID, run the stats cachedump command using the following syntax:

stats cachedump <slab_id> <limit>
  • <slab_id>: The numeric ID of the slab class obtained from stats items.
  • <limit>: The maximum number of keys to return. Setting this to 0 attempts to return all keys currently linked to that slab's LRU (Least Recently Used) list.

For example, to dump up to 10 keys from slab class 1:

stats cachedump 1 10

Interpreting the Output

The server responds with entries formatted as follows:

ITEM user_session_4815 [64 b; 1711929600 s]
ITEM user_session_4816 [128 b; 1711933200 s]
END
  • ITEM <key>: The name of the cached key (e.g., user_session_4815).
  • [<size> b;: The size of the cached value in bytes.
  • <timestamp> s]: The expiration time of the key represented as a Unix epoch timestamp. If the expiration timestamp is equal to or less than the current time, the key has expired or is set to expire immediately.

Operational Limitations

While stats cachedump is useful for debugging, administrators should be aware of several operational constraints:

  1. Incomplete Visibility: The command only dumps items linked to the top of the slab's LRU chain. On heavily loaded servers, it may not display every item in memory.
  2. Performance Impact: Dumping keys temporarily locks the cache. On large production instances, querying high limits can stall the Memcached process and increase latency for connected applications.
  3. Alternative for Modern Versions: In Memcached version 1.4.31 and newer, the non-blocking lru_crawler metadump all command is preferred for generating a comprehensive dump of all keys across all slabs without freezing the worker threads.
