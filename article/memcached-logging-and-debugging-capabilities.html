Memcached Logging and Debugging Capabilities

This article provides an overview of the logging, diagnostic, and debugging mechanisms built directly into the Memcached daemon (memcached) binary. It covers command-line verbosity flags, real-time log streaming via the watch interface, internal diagnostic stats commands, and compile-time tracing integrations like DTrace.

Command-Line Verbosity Flags

Memcached prints diagnostic and operational messages directly to standard output (stdout) or standard error (stderr). You can control the depth of these logs during process startup using verbosity flags:

  • -v (Verbose): Logs informational messages, startup configurations, warnings, and high-level errors.
  • -vv (Very Verbose): Logs incoming client requests, keys requested, storage actions, and server responses. This mode is useful for tracking application-level queries in a development environment.
  • -vvv (Extremely Verbose): Emits detailed internal state transitions, memory allocations, and event-loop executions. This flag produces high log volumes and should never be used under high-throughput production workloads.

To aid post-crash debugging, the -r flag instructs the binary to maximize core file limits (ulimit -c unlimited), allowing the generation of core dumps for inspection with tools like GDB.

Live Dynamic Logging: The watch Command

Memcached includes a dynamic log-monitoring system accessible over its standard ASCII protocol without needing to restart the daemon. By opening a TCP connection (via telnet or nc) to the Memcached port, administrators can issue the watch command to stream live internal events.

The watch command supports filtering by event categories:

  • watch fetchers: Displays cache lookups, cache hits, and cache misses in real time.
  • watch mutations: Streams write operations, including set, add, replace, and delete.
  • watch evictions: Alerts when items are evicted from slab classes due to memory constraints.

This interface allows granular inspection of production traffic with lower overhead than the -vv flag.

Runtime Inspection via stats Commands

The binary implements an extensive set of diagnostic commands via the Memcached protocol to inspect memory management, connection states, and cache efficiency:

  • stats: Returns general uptime, current connections, total items stored, memory usage, and cumulative hit/miss ratios.
  • stats settings: Dumps the running configuration, including max connections, thread count, slab limits, and memory limits.
  • stats items: Provides counts, age of oldest items, and eviction counts segmented by slab class ID.
  • stats slabs: Displays the low-level state of the slab memory allocator, chunk sizes, unused chunks, and memory waste.
  • stats conns: Lists active network connections, file descriptor usage, and current read/write states.

DTrace and SystemTap Probes

When compiled with the --enable-dtrace flag, the Memcached binary includes native User-Level Statically Defined Tracing (USDT) probes. These probes allow kernel-level tracing frameworks like DTrace, SystemTap, and eBPF to hook directly into the binary at runtime. They expose low-overhead monitoring for connection lifecycles, hash table lookups, memory allocation, and query execution times without modifying application code or restarting the daemon.
