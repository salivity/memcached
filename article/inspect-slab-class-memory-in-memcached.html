Inspect Slab Class Memory in Memcached

Memcached manages memory dynamically using a slab allocation system, grouping data into slab classes based on item size to prevent fragmentation. When troubleshooting memory issues, cache evictions, or inefficient allocation, several built-in diagnostic commands allow administrators to inspect memory usage across individual slab classes. This guide details the essential Memcached diagnostic commands—primarily stats slabs, stats items, and stats cachedump—and explains how to interpret their output to evaluate slab-level memory health.

Connecting to Memcached

To run diagnostic commands directly, establish a TCP connection to your Memcached instance via telnet or nc (netcat):

nc 127.0.0.1 11211

Once connected, you can type commands directly and press Enter.

1. stats slabs

The stats slabs command provides the most detailed breakdown of memory allocation per slab class. It shows how much physical memory has been committed to each class, how chunks are partitioned, and how much space is actively occupied.

Key Metrics to Monitor per Slab Class

Each slab class is prefixed by its numerical ID (e.g., STAT 1:chunk_size 96):

  • chunk_size: The maximum byte size of an item stored in this slab class.
  • chunks_per_page: The number of chunks allocated per 1 MB page for this class.
  • total_pages: The total number of 1 MB memory pages allocated to this slab class.
  • total_chunks: Total capacity (total_pages multiplied by chunks_per_page).
  • used_chunks: The number of chunks currently storing active data.
  • free_chunks: Chunks that have been allocated within a page but are not currently holding data.
  • free_chunks_end: Chunks at the end of the last allocated page that have never been used.
  • mem_requested: The actual byte count requested by the stored data (useful for calculating internal fragmentation: (used_chunks * chunk_size) - mem_requested).

Global Aggregates

At the end of the stats slabs output, global counters summarize overall memory health:

  • active_slabs: Total number of distinct slab classes in use.
  • total_malloced: Total memory allocated for all slab pages combined.

2. stats items

While stats slabs focuses on capacity and chunk allocations, stats items provides operational data about the items residing inside each slab class, including evictions and expiration behavior.

Key Metrics per Slab Class

  • number: Current number of stored items in this slab class.
  • age: Age of the oldest item in the slab class, measured in seconds since its last access.
  • evicted: The number of valid items evicted before expiration to make room for new items. High evictions in a specific slab class indicate that this class needs more memory.
  • evicted_time: Seconds since the last item was evicted.
  • outofmemory: The count of times the slab class could not store an item because memory limits were reached and eviction was disabled.
  • tailrepairs: Number of times the internal LRU tail required repair.

3. stats cachedump <slab_id> <limit>

To inspect the actual keys stored within a specific slab class, use stats cachedump. This command dumps a limited list of keys along with their size and expiration timestamp.

Syntax

stats cachedump <slab_class_id> <item_limit>

Example

stats cachedump 1 5
ITEM user_session_123 [96 b; 1711928400 s]
ITEM user_session_124 [96 b; 1711928400 s]
END

Note: In production environments, use this command with caution on heavily loaded instances, as dumping keys can briefly block server operations.

4. memcached-tool Command-Line Utility

If you have local shell access to the server, the Perl script memcached-tool formats the output of stats slabs and stats items into an easily readable terminal table:

memcached-tool 127.0.0.1:11211 display

This displays a columned view showing the Slab Class ID, Chunk Size, Max Storage, Item Count, Pages, Evictions, and Waste for every active slab.
