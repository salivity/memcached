Memcached Slab Page Size and Max Item Size

In Memcached, the slab page size and the maximum item size share a direct, 1:1 dependency: the slab page size defines the absolute upper limit for the maximum item size that can be stored. Because Memcached utilizes a slab allocation system where individual items cannot span multiple memory pages, an item—including its key, metadata, and value—must fit entirely within a single page chunk. Understanding this relationship is critical for configuring memory allocation, avoiding unexpected storage errors, and maintaining high cache efficiency.

The Mechanics of the Slab Allocator

Memcached avoids operating system-level memory fragmentation by pre-allocating memory in large blocks known as slab pages. By default, each slab page is 1 megabyte (1MB) in size.

These pages are assigned to specific "slab classes." Within a slab class, the page is sliced into smaller, equally sized partitions called chunks. For example, one slab class might hold chunks of 128 bytes, while another holds chunks of 1 kilobyte. When an item is stored, Memcached identifies the slab class with chunk dimensions closest to, but not smaller than, the total size of the item.

The Direct Dependency

Because an item must reside completely inside a single chunk, and chunks are created by dividing a single page, a chunk can never be larger than the page itself. Consequently:

  • Slab Page Size = Maximum Chunk Size = Maximum Item Size.
  • Memcached does not support chunking across multiple pages (no memory segmentation or page-spanning for a single record).
  • If an incoming item exceeds the slab page size, Memcached rejects it with an error (e.g., SERVER_ERROR object too large for cache).

By default, since the slab page size is 1MB, the maximum allowable item size is also 1MB.

Configuring Page and Item Sizes

Modern versions of Memcached allow you to adjust this limit using the -I (or --max-item-size) command-line flag during daemon startup. This single argument alters both parameters simultaneously:

memcached -I 5m

In this example, specifying 5m sets both the slab page size and the maximum item size to 5 megabytes. The minimum allowable page size is typically 1 kilobyte, and the maximum defaults to 1024 megabytes, depending on system architecture and compile-time flags.

Operational Trade-offs

Increasing the slab page size to accommodate larger items carries operational consequences:

  1. Memory Waste (Internal Fragmentation): If you increase the page size to 10MB to accommodate a handful of large objects, Memcached will allocate memory in 10MB increments for all slab classes. If your cache primarily stores small items (e.g., 200 bytes), memory overhead and wasted space per slab increase significantly.
  2. Network and Thread Blocking: Memcached is optimized for high-throughput, small-payload operations. Storing and retrieving multi-megabyte payloads can saturate network buffers, increase latency, and degrade the responsiveness of the worker threads.

To maintain optimal performance, the slab page size should be kept as close to the default 1MB as possible, scaling up only when larger single payloads are strictly necessary.
