Memcached Max Connection Backlog Parameter

This article explains the specific configuration parameter used to control the maximum pending network connection backlog in Memcached. It details how the setting works, how to configure it on your server, and the operating system limitations that directly impact its effectiveness during periods of high traffic.

The Connection Backlog Parameter: -b

In Memcached, the configuration parameter that controls the maximum backlog of pending network connections is -b (or backlog).

When clients attempt to establish a TCP connection with Memcached, the connections sit in a queue waiting to be processed by the server's listener thread. The -b flag sets the size of this queue via the underlying system listen() call.

By default, Memcached sets the backlog limit to 1024 connections.

How to Configure the Backlog

You can adjust this parameter either directly via the command-line interface when starting the daemon or within the Memcached configuration file.

Command-Line Usage

To start Memcached with a custom backlog limit, pass the -b flag followed by the desired integer value:

memcached -b 2048 -u memcached -m 1024 -p 11211

Configuration File Usage

On Linux distributions using a configuration file (such as /etc/memcached.conf on Debian/Ubuntu or /etc/sysconfig/memcached on RHEL/CentOS), you can append the option.

For Debian/Ubuntu (/etc/memcached.conf):

-b 2048

For RHEL/CentOS (/etc/sysconfig/memcached):

OPTIONS="-b 2048"

Restart the Memcached service after making changes to the configuration file for them to take effect.

Operating System Level Dependencies

Configuring the -b parameter in Memcached does not guarantee that the operating system will honor the requested backlog size. The Linux kernel enforces its own global limit on socket listen backlogs via the net.core.somaxconn sysctl parameter.

If the value set with -b exceeds the kernel's somaxconn limit, the operating system will silently truncate the backlog to the somaxconn value.

Checking and Updating somaxconn

To check your current system limit:

sysctl net.core.somaxconn

To increase this limit to match or exceed your Memcached configuration, update it dynamically:

sudo sysctl -w net.core.somaxconn=2048

To make the change persistent across server reboots, add the following line to /etc/sysctl.conf:

net.core.somaxconn = 2048

When to Adjust the Backlog

Increasing the connection backlog is beneficial in high-throughput environments where clients experience connection timeouts, "connection refused" errors, or sudden bursts of new TCP connections. By expanding both the -b parameter and the kernel's somaxconn, Memcached can queue brief bursts of incoming requests without dropping packets.
