Best Hardware Configuration for Memcached Throughput

Achieving the highest throughput in enterprise Memcached deployments requires eliminating hardware-level bottlenecks across networking, memory architecture, and processor topology. Because Memcached is an in-memory, highly concurrent key-value store, standard horizontal scaling often falls short without deliberate bare-metal hardware selection. Maximum performance relies on balancing multi-channel high-frequency RAM, modern high-bandwidth network interfaces, and low-latency CPU core topologies with dedicated NUMA isolation.

High-Frequency CPUs and NUMA Topologies

Memcached scales linearly across multiple threads up to a threshold, after which internal lock contention limits performance gains. Modern enterprise processors, such as AMD EPYC (Genoa/Bergamo) or Intel Xeon Scalable (Sapphire/Emerald Rapids), provide the optimal balance when configured properly:

  • Clock Speed over Core Count: Prioritize CPUs with high base and boost frequencies (3.0 GHz or higher) over extreme core counts. Memcached performance per thread scales directly with raw clock speed and cache access times.
  • NUMA Node Isolation: Non-Uniform Memory Access (NUMA) traversals over interconnects like AMD Infinity Fabric or Intel UPI introduce significant memory latency. For maximum throughput, choose single-socket systems or strictly isolate memory access on dual-socket systems by running distinct Memcached processes pinned to specific NUMA domains using numactl.
  • Thread Tuning: Avoid running a single Memcached instance across more than 8 to 16 threads. For high-core-count servers, deploy multiple independent Memcached instances per host, binding each instance to a distinct set of physical CPU cores.

Memory Subsystem Configuration

Because all operations occur in RAM, memory bandwidth and latency dictate overall request serving speeds:

  • Full Channel Population: Modern enterprise architectures feature 8-channel or 12-channel memory interfaces. Ensure that every memory channel per socket is populated with identical DIMMs. Running in a suboptimal channel configuration directly reduces memory bandwidth.
  • High-Frequency, Low-Latency DDR5: Deploy DDR5-4800 or DDR5-5600 Registered ECC memory. The increased bandwidth of DDR5 significantly reduces wait states during high-concurrency read and write spikes.
  • Transparent Huge Pages (THP) Deactivation: While not purely a hardware specification, memory controllers must be paired with an OS configuration that disables Transparent Huge Pages. Memcached allocates memory in discrete slabs; THP introduces fragmentation, latency spikes, and page allocation stalls.

High-Bandwidth, Multi-Queue Networking

At high operations per second (OPS), the network subsystem is the most common hardware bottleneck. Standard 10GbE interfaces will saturate on packet rates long before modern CPUs reach full utilization:

  • 25GbE to 100GbE PCIe Gen 4/Gen 5 NICs: Deploy enterprise-grade network interfaces (such as NVIDIA Mellanox ConnectX-6 or ConnectX-7). These adapters sustain the packet-per-second (PPS) rates required to handle millions of queries per second.
  • Receive Side Scaling (RSS) and Multi-Queue Support: Ensure the network card supports hardware RSS with enough receive and transmit queues to allocate dedicated queues to each Memcached worker thread. Pin these network interrupts to the same CPU cores handling the corresponding worker threads to keep network processing within the local L3 cache.
  • Kernel Bypass and eBPF/XDP: For extreme throughput environments exceeding several million operations per second per node, consider running setups capable of utilizing DPDK (Data Plane Development Kit) or AF_XDP to bypass standard kernel network stack overhead.

Storage and PCIe Bus Considerations

While Memcached does not write active data to persistent storage, the system bus architecture impacts performance:

  • Dedicated PCIe Lanes: Ensure that network interface cards are installed in PCIe slots directly attached to the primary CPU socket, avoiding multiplexers or secondary PCIe switches that introduce latency.
  • High-Endurance NVMe for Operating System and Logging: Use enterprise NVMe storage strictly for system overhead, operating system logs, and metric collection to prevent I/O blocking from background operating system tasks affecting memory-resident processes.
