Essential Memcached Metrics for Health Dashboards

Monitoring Memcached is critical for ensuring reliable caching, preventing database overload, and maintaining sub-millisecond response times across distributed architectures. This article covers the essential operational metrics that must be charted on your health dashboards, focusing on memory saturation, eviction trends, cache hit rates, connection limits, and network throughput to help you detect anomalies and prevent service degradation before users are impacted.

Cache Efficiency Metrics

  • Hit Ratio (get_hits vs. get_misses): Calculate the hit ratio as get_hits / (get_hits + get_misses). A healthy cache typically sustains an 85% to 99% hit rate depending on the workload. Sudden drops indicate expiring data, aggressive evictions, invalidation bugs, or changes in application traffic patterns.
  • Command Rates (cmd_get, cmd_set, cmd_delete): Tracking throughput by command type shows the read/write distribution. A sudden spike in cmd_set without a corresponding increase in cmd_get points to inefficient write-heavy patterns or cache thrashing.

Memory Utilization and Evictions

  • Memory Usage (bytes vs. limit_maxbytes): Track the percentage of available memory consumed. Operating near 100% capacity is normal for Memcached, but it must be evaluated directly alongside eviction counts.
  • Evictions (evictions): The number of valid items removed to free up space for new items before their TTL expires. A continuously climbing eviction rate signals that the cache is undersized for its working set, forcing the database to handle unnecessary traffic.
  • Reclaimed Items (reclaimed): The number of times expired items were overwritten by new writes. High reclamation with zero evictions represents healthy, optimized memory recycling.

Connection Health

  • Current Connections (curr_connections): Shows the number of open client connections. Unexpected spikes often reveal connection leaks in upstream application servers or connection pool misconfigurations.
  • Connection Failures and Limits (listen_disabled_num): This is a critical operational threshold metric. When Memcached reaches its maximum configured connection limit (-c flag), listen_disabled_num increments, and new client connections are refused. This metric should remain at zero; any value above zero requires immediate alerting.

Network and I/O Throughput

  • Traffic Volume (bytes_read and bytes_written): Charting the volume of incoming and outgoing data helps detect network interface saturation. Disproportionate spikes in bytes_written usually signify that excessively large payloads or uncompressed objects are being stored.
  • Rejected Connections due to Exhaustion: Track server-side network drop rates to identify socket backlog saturation or OS-level file descriptor limits (nofile).

System and Hardware Resources

  • CPU Utilization (rusage_user and rusage_system): While Memcached is highly efficient and multi-threaded, high CPU usage can stem from extreme connection churn or lock contention under heavy multi-key get operations.
  • Thread Worker Stats: Monitor worker thread utilization to ensure requests are evenly distributed across allocated execution threads.
