Memcached Text Protocol Debugging with Telnet

The Memcached text protocol offers a human-readable, command-driven interface that enables direct troubleshooting and manual cache inspection using standard network utilities like Telnet and Netcat. This article outlines the primary features of the protocol that facilitate manual debugging, including human-readable command execution, live key inspection, slab allocation analysis, and server state diagnostics.

Plain-Text, Line-Based Communication

The protocol operates entirely over readable ASCII strings terminated by standard carriage returns and line feeds (\r\n). Because it does not require binary framing or client-side serialization to communicate basic commands, an engineer can open a raw TCP socket (telnet localhost 11211 or nc localhost 11211) and immediately type commands to observe direct responses.

Explicit Storage and Retrieval Verification

The protocol separates command parameters into clean, space-delimited arguments, allowing you to manually verify how data behaves inside the cache:

  • Direct Data Writes: Using set, add, replace, append, and prepend, you can specify explicit metadata including 32-bit flags, expiration times (TTL in seconds or UNIX timestamps), and exact byte lengths. This makes it trivial to test edge cases such as zero-second expirations or data truncation.
  • Direct Data Reads: Running get <key> or gets <key> displays the stored value along with its metadata flags and Check-And-Set (CAS) tokens, allowing you to verify that objects are not silently dropped or corrupted.
  • Deterministic Status Messages: Instead of numeric error codes, the server replies with unambiguous text strings such as STORED, NOT_STORED, EXISTS, and NOT_FOUND, making validation immediate.

Granular Server Metrics via the stats Command Family

Debugging performance degradation, cache misses, or memory pressure is heavily supported by specialized stats subcommands:

  • General System Diagnostics (stats): Displays overall server health, including uptime, memory usage, current active connections, cumulative hits, misses, and eviction counts.
  • Memory and Slab Inspection (stats slabs): Reports chunk sizes, allocated pages, and memory waste across individual slab classes to identify memory fragmentation or poor item distribution.
  • Item Distribution (stats items): Lists item counts, age of the oldest item, and eviction rates per slab class to diagnose why specific data types are being purged prematurely.
  • Key Sampling (stats cachedump <slab_id> <limit>): Allows manual extraction of key names, item sizes, and expiration timestamps from specific slab classes, enabling inspection of resident keys without a dedicated monitoring client.

Environment and State Control

The text protocol provides basic administrative utilities directly through the terminal:

  • flush_all: Invalidate all active keys globally, either immediately or with a timed delay, which is useful for setting up reproducible test conditions.
  • version: Confirms the active Memcached release to rule out version-specific bugs or incompatibilities.
  • verbosity <level>: Adjusts the verbosity level of server-side logging dynamically without requiring a process restart.

Verbose Error Handling

When a syntax error occurs or malformed data is sent, the text protocol responds with informative errors categorizing the fault:

  • ERROR: The submitted command does not exist.
  • CLIENT_ERROR <message>: The input failed validation (e.g., mismatched byte length or non-numeric arguments).
  • SERVER_ERROR <message>: The server encountered an internal failure or out-of-memory condition.

These distinct error classes provide immediate clarity during manual sessions on whether an issue stems from improper client requests or internal server limits.
