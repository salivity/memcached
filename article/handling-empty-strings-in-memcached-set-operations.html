Handling Empty Strings in Memcached Set Operations

Memcached fully supports zero-length values and empty strings during set operations, treating them as valid cache entries rather than null values or errors. This article explains how the Memcached protocol processes empty values, how the internal memory allocation engine handles zero-byte payloads, and the operational implications of storing empty strings.

Protocol Level Behavior

In the Memcached text protocol, a storage command follows the format:

set <key> <flags> <exptime> <bytes> [noreply]\r\n<data>\r\n

When storing an empty string or zero-length value, the <bytes> parameter is set to 0. The client then sends the terminating carriage return and line feed (\r\n) immediately without any preceding data payload.

Example command:

set user:100:active 0 3600 0\r\n
\r\n

Upon receiving this request, Memcached writes the entry and returns:

STORED\r\n

When retrieving the item using get user:100:active, Memcached returns a header indicating a length of zero, followed by the empty data block and the standard END marker:

VALUE user:100:active 0 0\r\n
\r\n
END\r\n

The binary protocol behaves identically: the body length field in the request header matches the key length, resulting in a value length of zero. The server processes the command successfully and returns a successful response status (0x0000).

Memory Allocation and Overhead

Setting a value of zero bytes does not consume zero memory. Memcached uses a slab allocator that assigns memory in fixed-size chunks.

Every cached entry requires an internal item metadata header, which includes:

  • Key string and key length
  • Flags (32-bit integer)
  • Expiration time
  • Memory management and LRU pointers
  • CAS (Check-And-Set) identifier (if enabled)

Because of this metadata and the key itself, an item with a 0-byte value will be placed in the smallest available slab class (typically 96 or 104 bytes by default, depending on key length and architecture). Storing an empty string consumes the memory allocated for that entire minimum chunk size.

Lifecycle and Operations

A zero-length item is treated like any standard item in the cache:

  • Expiration (TTL): Time-to-live settings function normally. Once the expiration time passes, the key becomes inaccessible and is freed.
  • LRU Eviction: If memory limits are reached, zero-length entries are evaluated and evicted based on standard Least Recently Used (LRU) rules.
  • Conditional Operations: Operations such as add, replace, and cas apply the same logic. For example, add key 0 0 0 will fail if the key already exists, regardless of the value length.
  • Append and Prepend: Running append or prepend on an existing zero-length item appends data to the empty buffer, successfully expanding the value.

Common Use Cases

Storing zero-length values is a common optimization pattern in Memcached for:

  • Existence Tracking: Indicating that an ID or record exists (e.g., membership sets) using keys alone, eliminating payload transmission overhead.
  • Negative Caching: Storing a flag to indicate that a queried database record does not exist, preventing repeated database lookups for missing records.
  • Distributed Mutexes: Using add with a zero-length payload to acquire lightweight locks with minimal network overhead.
