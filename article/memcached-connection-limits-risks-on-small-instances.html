Memcached Connection Limits: Risks on Small Instances

Configuring high connection limits on small Memcached instances exposes infrastructure to severe stability and performance hazards. While administrators often increase these limits to prevent "connection refused" errors during traffic spikes, small instances lack the compute and memory reserves needed to service high concurrency. This mismatch frequently leads to memory exhaustion, CPU thread starvation, file descriptor depletion, and cascading application failures.

Memory Overhead and Cache Starvation

Every TCP connection established to a Memcached server consumes memory beyond the application's actual data payload. Memcached allocates internal structures to track each connection, while the operating system kernel allocates read and write socket buffers (typically managed by tcp_rmem and tcp_wmem).

On small instances with limited RAM (such as 512MB to 2GB), thousands of concurrent connections—even if largely idle—can consume hundreds of megabytes in networking overhead alone. Because this memory is dynamically allocated by the kernel and the daemon's connection pool, it directly competes with the configured item cache space. If connection allocations outpace available headroom, Memcached must aggressively evict cached data, resulting in plummeting hit rates and increased load on primary data stores.

Out of Memory (OOM) Process Termination

When the combined footprint of the Memcached process, connection state metadata, and kernel socket buffers exceeds the physical RAM of a small instance, the host enters a memory-starved state. Because Memcached typically does not use swap space to ensure low-latency operations, the Linux Out-of-Memory (OOM) Killer will be triggered. The kernel frequently selects the memcached process itself as the target for termination, causing a total node outage that immediately drops all active connections and wipes the entire volatile cache.

CPU Saturation and Event Loop Latency

Memcached relies on an event-driven architecture using libevent alongside a set number of worker threads. While highly efficient, managing tens of thousands of active file descriptors on an instance with only one or two vCPUs introduces heavy overhead.

The CPU spends an increasing percentage of its cycles processing kernel interrupts, socket polling (via epoll), and thread context switching rather than executing read and write commands. This bottleneck inflates p99 response latencies. As latency mounts, requests queue up, clients hold connections open longer to await responses, and the server enters a vicious cycle of self-reinforcing congestion.

File Descriptor and Network Stack Depletion

Allowing a high connection limit on Memcached requires a commensurate increase in the operating system's open file limit (nofile). Small virtual machines often run default system configurations that bottleneck long before reaching Memcached's configured maximum.

If the file descriptor limit is reached, Memcached will fail to accept new sockets, generating system-level errors and silently dropping connection attempts. Additionally, tracking thousands of half-open or rapidly churning connections can saturate the kernel's connection tracking tables (conntrack) and exhaust the local ephemeral port range, disrupting host-level networking altogether.

Cascading Downstream Failures

A degraded Memcached instance inevitably destabilizes the surrounding architecture. When an overloaded small instance begins timing out or dropping connections:

  1. Client Thread Exhaustion: Upstream web servers and microservices hold their own worker threads open while waiting for Memcached queries to complete.
  2. Thundering Herd Effects: As the cache becomes unresponsive or drops items due to memory pressure, queries bypass the caching layer and hit primary databases simultaneously.
  3. Connection Storms: Automated client retries initiate thousands of new handshakes against an already drowning Memcached instance, finalizing the total collapse of the caching tier and exposing downstream databases to unsustainable traffic.
