Inspect Active Memcached Configuration

This article explains how to inspect the current active configuration of a running Memcached daemon using built-in administrative commands. You will learn the specific command required to view active settings, how to execute it via common command-line utilities, and how to interpret the most important configuration parameters returned by the server.

The Command: stats settings

To inspect the runtime settings of a Memcached daemon, the command to use is:

stats settings

When issued to the Memcached service, this command returns key-value pairs representing the daemon's active operational parameters, including memory limits, connection thresholds, network bindings, and protocol configurations.

How to Execute the Command

Memcached communicates via a plain-text protocol over its designated TCP port (default: 11211). You can issue the stats settings command using several command-line tools.

Using Netcat (nc)

Netcat provides a fast, non-interactive way to query the daemon:

echo "stats settings" | nc 127.0.0.1 11211

Using Telnet

For an interactive session, establish a connection with Telnet:

telnet 127.0.0.1 11211

Once connected, type stats settings and press Enter. Type quit and press Enter to exit the session.

Using memcached-tool

Many Linux distributions package an administrative Perl script named memcached-tool. You can view the configuration by running:

memcached-tool 127.0.0.1:11211 settings

Key Configuration Parameters Explained

The output produces a list of all active parameters. The most critical settings include:

  • maxbytes: The maximum amount of memory (in bytes) allocated to the cache.
  • maxconns: The maximum number of simultaneous client connections allowed.
  • tcpport / udpport: The active network ports listening for incoming traffic.
  • inter: The network interface/IP address the daemon is bound to.
  • verbosity: The current logging level (0 = quiet, 1 = verbose, 2 = very verbose).
  • evictions: Indicates whether object eviction is enabled (on or off) when memory is full.
  • binding_protocol: Specifies the accepted protocols (e.g., ascii, binary, or auto-negotiate).

Using stats settings ensures operators can verify operational states directly against the running process without relying on static configuration files that may not reflect real-time daemon states.
