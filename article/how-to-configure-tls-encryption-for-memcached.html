How to Configure TLS Encryption for Memcached

Memcached does not enable encryption by default, exposing cached data in transit across internal networks unless explicitly secured. Modern versions of Memcached (version 1.5.13 and later) natively support Transport Layer Security (TLS) to encrypt traffic between clients and the cache cluster. This guide explains how to secure Memcached using TLS encryption by preparing digital certificates, configuring and launching the Memcached server with SSL/TLS parameters, and configuring client applications to establish encrypted connections.

Prerequisites

To configure TLS for Memcached, you need:

  • Memcached version 1.5.13 or newer compiled with TLS support.
  • OpenSSL libraries and development headers installed (openssl, libssl-dev on Debian/Ubuntu or openssl-devel on RHEL/CentOS).
  • An existing Public Key Infrastructure (PKI) or self-signed certificates for testing: a Certificate Authority (CA) certificate, a server certificate, and a corresponding private key.

If compiling Memcached from source, enable the TLS flag during configuration:

./configure --enable-tls
make
sudo make install

Step 1: Generate TLS Certificates

For development or internal testing, generate a root CA and server certificates using OpenSSL:

# Generate CA private key and certificate
openssl genrsa -out ca-key.pem 2048
openssl req -x509 -new -nodes -key ca-key.pem -days 365 -out ca-cert.pem -subj "/CN=Memcached-CA"

# Generate server private key and Certificate Signing Request (CSR)
openssl genrsa -out server-key.pem 2048
openssl req -new -key server-key.pem -out server.csr -subj "/CN=memcached.internal"

# Sign the server certificate using the CA
openssl x509 -req -in server.csr -CA ca-cert.pem -CAkey ca-key.pem -CAcreateserial -out server-cert.pem -days 365

Place server-cert.pem, server-key.pem, and ca-cert.pem into a secure directory, such as /etc/memcached/certs/, and restrict permissions:

chmod 600 /etc/memcached/certs/server-key.pem
chmod 644 /etc/memcached/certs/server-cert.pem /etc/memcached/certs/ca-cert.pem

Step 2: Configure the Memcached Server

To enable TLS, pass the -Z (or --enable-ssl) flag along with the certificate parameters to the memcached binary.

Command-Line Execution

Run Memcached directly with the required TLS options:

memcached -p 11211 \
  -u memcached \
  -m 1024 \
  -Z \
  -o ssl_chain_cert=/etc/memcached/certs/server-cert.pem \
  -o ssl_key=/etc/memcached/certs/server-key.pem \
  -o ssl_ca_cert=/etc/memcached/certs/ca-cert.pem \
  -o ssl_verify_mode=1

Key TLS arguments:

  • -Z or --enable-ssl: Activates SSL/TLS mode on all listening ports.
  • ssl_chain_cert: Path to the server's public certificate or certificate chain.
  • ssl_key: Path to the server's private key.
  • ssl_ca_cert: Path to the CA certificate used for validating client certificates (if client authentication is enabled).
  • ssl_verify_mode: Set to 0 for none, 1 to request a client certificate, or 2 to strictly require valid client certificates (mutual TLS).

Systemd Service Configuration

If managing Memcached through systemd, edit /etc/memcached.conf or the systemd environment file (e.g., /etc/sysconfig/memcached or /etc/default/memcached):

-Z
-o ssl_chain_cert=/etc/memcached/certs/server-cert.pem
-o ssl_key=/etc/memcached/certs/server-key.pem
-o ssl_ca_cert=/etc/memcached/certs/ca-cert.pem
-o ssl_verify_mode=1

Restart the service to apply the configuration:

sudo systemctl restart memcached

Step 3: Verify TLS on the Server

Test whether Memcached is listening and requiring TLS by using openssl s_client:

openssl s_client -connect 127.0.0.1:11211 -CAfile /etc/memcached/certs/ca-cert.pem

If the handshake succeeds, the OpenSSL session details will appear. Enter standard Memcached commands like version or stats to verify that the daemon processes input over the encrypted channel. Plaintext connections (e.g., via standard telnet or nc) will now fail or be rejected immediately.

Step 4: Configure Client Applications

Clients must explicitly establish a TLS connection and trust the CA that signed the Memcached server certificate.

Python (pymemcache)

import ssl
from pymemcache.client.base import Client

context = ssl.create_default_context(cafile="/path/to/ca-cert.pem")

# If mutual TLS (mTLS) is enabled on the server:
# context.load_cert_chain(certfile="/path/to/client-cert.pem", keyfile="/path/to/client-key.pem")

client = Client(
    ("127.0.0.1", 11211),
    tls_context=context
)

client.set("secure_key", "secure_value")
print(client.get("secure_key"))

PHP (php-memcached)

In PHP, the memcached PECL extension must be compiled against OpenSSL, or options must be supplied through stream configurations or custom options:

$m = new Memcached();
$m->setOption(Memcached::OPT_BINARY_PROTOCOL, true);

// Configure TLS credentials where supported by libmemcached
$m->setOption(Memcached::OPT_SSL, true);
$m->setOption(Memcached::OPT_SSL_CA_CERT, '/path/to/ca-cert.pem');
$m->setOption(Memcached::OPT_SSL_KEY, '/path/to/client-key.pem');
$m->setOption(Memcached::OPT_SSL_CERT, '/path/to/client-cert.pem');

$m->addServer('127.0.0.1', 11211);
$m->set('secure_key', 'secure_value');

Node.js (memjs)

const memjs = require('memjs');

const client = memjs.Client.create('127.0.0.1:11211', {
  sslOptions: {
    ca: [fs.readFileSync('/path/to/ca-cert.pem')]
  }
});

client.set('secure_key', 'secure_value', {}, (err, val) => {
  if (!err) console.log('Value stored securely');
});

Enabling TLS adds minor cryptographic overhead, but ensures full confidentiality and data integrity across distributed networks hosting Memcached clusters.
