Memcached Evicted Keys Metric Explained

This article identifies the specific Memcached metric used to track the cumulative number of evicted keys since startup, explains how to retrieve it, and outlines what this data means for your caching layer's performance. By monitoring this value, administrators can determine whether their cache size is adequate or if premature evictions are hurting application efficiency.

The Evictions Metric

In Memcached, the metric that reports the cumulative number of evicted keys since startup is evictions.

An eviction occurs when Memcached runs out of allocated memory for a specific slab class and must delete valid, non-expired items according to its Least Recently Used (LRU) algorithm to make room for newly incoming data. Expired items that are reclaimed do not count toward this metric; it tracks only valid, unexpired items that were forcibly removed due to memory constraints.

How to View the Metric

You can inspect the evictions metric by connecting directly to your Memcached instance via telnet or nc (netcat) and issuing the general statistics command:

echo "stats" | nc 127.0.0.1 11211

Among the returned key-value pairs, look for the evictions entry:

STAT rusage_system 0.140000
STAT curr_items 45021
STAT total_items 152003
STAT bytes 34125800
STAT maxbytes 67108864
STAT evictions 12845
END

In this output, STAT evictions 12845 indicates that 12,845 valid keys have been removed to free up memory since the daemon was last started.

For more granular tracking, Memcached also provides slab-level eviction statistics. Running stats items displays the evicted count partitioned by each individual slab class ID.

Interpreting Eviction Counts

A non-zero or rapidly increasing evictions count indicates that your cache working set is larger than the memory allocated to Memcached.

  • Stable or Zero Evictions: The cache size is sufficient to hold the active working set, and keys are generally expiring naturally via their Time-To-Live (TTL).
  • Growing Evictions: Active data is being pushed out prematurely. This often results in a lower cache hit ratio and increased query load on the underlying database.

To resolve high eviction rates, consider increasing the maximum memory allocation limit using the -m flag, optimizing item TTLs so stale data expires sooner, or scaling out across additional Memcached nodes.
