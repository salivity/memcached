Custom Hash Functions in Memcached Clients

This article explores how developers can implement and configure custom hash functions within Memcached client libraries to control key distribution across clusters. It covers the role of client-side hashing in distributed caching, the reasons for overriding default hashing logic, and concrete implementation examples across popular programming languages such as Java, Python, and C/C++. Finally, it outlines best practices for selecting and testing custom hash algorithms to maintain uniform distribution and high throughput.

Understanding Client-Side Hashing in Memcached

Memcached servers operate independently in a cluster without native inter-node communication or built-in sharding. As a result, the responsibility of determining which server stores a given key falls entirely on the client library.

The client library performs this operation in two phases:

  1. Key Hashing: Computing a 32-bit or 64-bit integer from the key using a hashing algorithm (such as CRC32, FNV-1a, or MurmurHash).
  2. Server Mapping: Mapping the resulting hash to a specific server, typically using modulo arithmetic or consistent hashing (like the Ketama algorithm).

Developers often implement custom hash functions to guarantee consistent routing across heterogeneous application environments (for example, ensuring Java and Go microservices map identical keys to the same cache nodes) or to mitigate hotspotting caused by poor default key distribution.

Implementing Custom Hash Functions Across Client Libraries

1. Java (spymemcached)

In spymemcached, the hashing mechanism is defined by the HashAlgorithm interface. To implement a custom hash function:

  1. Create a class implementing net.spy.memcached.HashAlgorithm.
  2. Override the hash(String k) method to return a long.
  3. Provide the custom implementation to the ConnectionFactoryBuilder.
import net.spy.memcached.ConnectionFactoryBuilder;
import net.spy.memcached.HashAlgorithm;
import net.spy.memcached.MemcachedClient;
import java.net.InetSocketAddress;
import java.util.Collections;

public class CustomMemcachedExample {
    public static void main(String[] args) throws Exception {
        HashAlgorithm customMurmur = new HashAlgorithm() {
            @Override
            public long hash(final String k) {
                // Custom 32-bit or 64-bit hash logic
                return customHashLogic(k.getBytes());
            }

            private long customHashLogic(byte[] bytes) {
                long hash = 0xcbf29ce484222325L;
                for (byte b : bytes) {
                    hash ^= (b & 0xff);
                    hash *= 0x100000001b3L;
                }
                return hash;
            }
        };

        ConnectionFactoryBuilder builder = new ConnectionFactoryBuilder();
        builder.setHashAlg(customMurmur);
        builder.setLocatorType(ConnectionFactoryBuilder.Locator.CONSISTENT);

        MemcachedClient client = new MemcachedClient(
            builder.build(), 
            Collections.singletonList(new InetSocketAddress("localhost", 11211))
        );

        client.set("key", 3600, "value");
    }
}

2. Python (pymemcache)

pymemcache supports custom key hashing via custom client configurations or by wrapping cluster implementations. When using pymemcache.client.hash.HashClient, developers can provide a custom hasher function:

from pymemcache.client.hash import HashClient

def custom_hasher(key):
    """Computes a custom 32-bit integer hash for a string key."""
    if isinstance(key, str):
        key = key.encode('utf-8')
    
    # Example: Simple FNV-1a 32-bit implementation
    fnv_prime = 16777619
    hash_val = 2166136261
    for byte in key:
        hash_val ^= byte
        hash_val = (hash_val * fnv_prime) & 0xFFFFFFFF
    return hash_val

servers = [('127.0.0.1', 11211), ('127.0.0.1', 11212)]

# Pass the custom hasher to the HashClient
client = HashClient(
    servers,
    hasher=custom_hasher,
    use_pooling=True
)

client.set('custom_key', 'stored_value')

3. C / C++ (libmemcached)

The libmemcached library provides a native behavior-setting API that allows developers to define custom callbacks for hashing.

  1. Implement a function matching the signature uint32_t (*memcached_hash_fn)(const char *key, size_t key_length, void *context).
  2. Apply the callback using memcached_behavior_set_key_hash().
#include <libmemcached/memcached.h>
#include <string.h>

uint32_t custom_hash(const char *key, size_t key_length, void *context) {
    uint32_t hash = 5381;
    for (size_t i = 0; i < key_length; ++i) {
        hash = ((hash << 5) + hash) + key[i];
    }
    return hash;
}

int main() {
    memcached_st *memc = memcached_create(NULL);

    // Set custom key hashing function
    memcached_behavior_set_key_hash(memc, MEMCACHED_HASH_CUSTOM);
    memcached_set_hash_callback(memc, custom_hash, NULL);

    // Proceed with adding servers and setting keys...
    memcached_free(memc);
    return 0;
}

4. Go (gomemcache)

The official bradfitz/gomemcache library uses the ServerList struct to implement the ServerSelector interface. To provide a custom hash:

  1. Implement the gomemcache.ServerSelector interface.
  2. In the PickServer(key string) method, apply the custom hash function and map it to an available server address.
package main

import (
    "net"
    "sync"
    "github.com/bradfitz/gomemcache/memcache"
)

type CustomSelector struct {
    mu      sync.RWMutex
    servers []net.Addr
}

func (s *CustomSelector) PickServer(key string) (net.Addr, error) {
    s.mu.RLock()
    defer s.mu.RUnlock()

    if len(s.servers) == 0 {
        return nil, memcache.ErrNoServers
    }

    // Compute custom hash
    var hash uint32 = 2166136261
    for i := 0; i < len(key); i++ {
        hash ^= uint32(key[i])
        hash *= 16777619
    }

    return s.servers[hash%uint32(len(s.servers))], nil
}

func (s *CustomSelector) Each(f func(net.Addr) error) error {

    defer s.mu.RUnlock()
    for _, a := range s.servers {
        if err := f(a); err != nil {
            return err
        }
    }
    return nil

Best Practices for Custom Hash Functions

  • Uniform Distribution: Select algorithms such as MurmurHash3, CityHash, or xxHash that minimize collision rates and eliminate clustering across buckets.
  • Cross-Platform Compatibility: When using multiple programming languages in the same infrastructure, ensure identical character encoding (typically UTF-8), integer widths, and endianness handling.
  • Consistent Hashing Integration: Apply the custom hash function as the base integer generator within a consistent hashing ring (Ketama) rather than using direct modulo arithmetic, preventing mass cache invalidation during node scaling.
  • Speed and Efficiency: Key hashing executes synchronously on every cache read and write. Choose non-cryptographic hashes that process input in \(O(N)\) time with minimal allocation overhead.
