Inspect Slab Page Allocations in Memcached

This article explains how to inspect slab page allocation counts in Memcached to optimize memory usage and troubleshoot caching issues. By using built-in administrative commands, operators can monitor memory distribution across slab classes, identify memory fragmentation, and verify how many 1MB memory pages each slab class currently holds.

The Command: stats slabs

The primary command used to inspect slab page allocation counts in Memcached is stats slabs.

Memcached manages memory by dividing allocated RAM into slabs, which are further partitioned into equal-sized chunks suited for specific item size ranges. Running stats slabs produces detailed statistics for every active slab class in the daemon, including the total number of pages assigned to each class.

How to Execute the Command

Operators can send the command directly over a TCP connection using tools like nc (netcat) or telnet.

Using netcat:

echo "stats slabs" | nc 127.0.0.1 11211

Using telnet:

telnet 127.0.0.1 11211
stats slabs
quit

Alternatively, the memcached-tool utility (included with many Linux distributions) can display this information in a formatted table:

memcached-tool 127.0.0.1:11211 display

Interpreting Page Allocation Metrics

The output of stats slabs lists key-value pairs categorized by slab class identifier (e.g., 1, 2, 3). To track page allocations, look for the following metrics:

  • <slabclass>:total_pages: The number of 1MB pages assigned to this specific slab class. This is the exact metric indicating page allocation counts.
  • <slabclass>:chunk_size: The size in bytes of each chunk within the slab.
  • <slabclass>:chunks_per_page: The number of chunks that fit into a single 1MB page.
  • <slabclass>:used_chunks: The number of allocated chunks currently storing data.
  • <slabclass>:free_chunks: The number of allocated chunks available for new items without allocating a new page.
  • active_slabs: The total count of active slab classes in the system.
  • total_malloced: Total memory allocated for all slabs combined.

Why Monitoring Slab Allocations Matters

Once a page is assigned to a slab class, older Memcached versions lock that page to that class permanently. In modern versions, the slab automove feature (slab_automove) reallocates pages dynamically, but monitoring total_pages remains vital. Disproportionately high page counts in rarely used slab classes indicate memory skew, while classes consistently running out of free chunks can lead to unnecessary evictions.
