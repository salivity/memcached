How Memcached Rebalances Slabs Automatically

Memcached addresses shifting memory demands and prevents memory calcification through a background mechanism known as Slab Automove, which operates alongside the Slab Reassign feature. This article explains how memory calcification occurs in Memcached, how the Slab Reassign engine primitive functions, and how the Slab Automove thread continuously monitors item eviction patterns to dynamically transfer 1MB memory pages between slab classes without service interruption.

The Challenge of Slab Calcification

Memcached manages memory using a slab allocator. It divides memory into 1MB pages, which are then assigned to specific slab classes tailored to store items within defined size ranges. By default, once a 1MB page is allocated to a specific slab class, it remains assigned to that class indefinitely.

If an application's data profile changes—for instance, transitioning from storing many 100-byte objects to storing 2-kilobyte objects—the memory can become "calcified." In a calcified state, slab classes holding older, smaller data types retain unused or rarely accessed memory, while slab classes handling the new, larger data types run out of space and begin aggressively evicting active keys.

The Slab Reassign Engine

To solve calcification, Memcached implemented Slab Reassign. Slab Reassign is the low-level primitive that physically moves a 1MB page from a donor slab class to a receiver slab class.

When a slab reassign occurs:

  1. A 1MB page in the donor slab class is selected.
  2. The items residing on that page are invalidated or evicted.
  3. The page is detached from the donor slab class.
  4. The page is reassigned and partitioned according to the chunk size of the target slab class.

While Slab Reassign can be triggered manually via administrative console commands, it is best utilized automatically through background monitoring.

The Slab Automove Mechanism

Slab Automove is an integrated background maintenance thread that monitors cache activity and automatically executes slab_reassign operations when it detects uneven memory pressure. It monitors key metrics such as eviction frequency, page utilization, and data age across all slab classes.

When enabled, the automove thread periodically samples memory metrics (typically once per second) and decides whether to move pages based on configured heuristic algorithms:

1. Standard Automove (Algorithm 1)

The standard algorithm looks for persistent imbalances over a sliding time window (typically three consecutive sampling periods):

  • Source Identification: It looks for a slab class that has completely free memory pages or has not had to evict any items recently.
  • Target Identification: It looks for a slab class that is actively evicting items due to space exhaustion.
  • If a class evicts items across three monitoring intervals and another class has unallocated pages or idle memory, one 1MB page is reassigned from the idle class to the struggling class.

2. Age-Based Automove (Algorithm 2)

Introduced to work closely with Memcached's modern segmented LRU (Least Recently Used) design, Algorithm 2 relies on the tail age of items:

  • It analyzes the age of the oldest items (tail age) across the different slab classes.
  • If items in Slab Class A are being evicted after living for only 60 seconds, while items in Slab Class B are surviving untouched for days, the automover recognizes an imbalance in cache efficiency.
  • Pages are systematically moved from the class with significantly older tail items to the class with premature evictions, balancing eviction ages across the entire system.

Enabling and Configuring Slab Rebalancing

To utilize automatic slab rebalancing, Memcached must be started with slab reassignment enabled, along with the desired automove algorithm:

  • -o slab_reassign: Enables the underlying memory reassignment capability.
  • -o slab_automove=<0|1|2>: Sets the automove behavior:
    • 0: Standby mode (reassign is enabled, but automove is disabled; moves must be triggered manually).
    • 1: Standard algorithm (conservative; triggers on continuous evictions and free pages).
    • 2: Aggressive/Age-based algorithm (rebalances pages to equalize the LRU tail age across classes).

These parameters allow Memcached instances to adapt to fluctuating traffic and data structures over time, maintaining optimal hit rates without requiring cache restarts or manual maintenance.
