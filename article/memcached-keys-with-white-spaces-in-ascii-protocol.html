Memcached Keys With White Spaces in ASCII Protocol

This article explains how Memcached interprets keys containing white spaces when using the standard ASCII protocol. In Memcached's text-based protocol, spaces function strictly as command and argument delimiters. As a result, genuine key names cannot contain spaces; attempting to use them will either trigger a command syntax error or cause the server to parse the single key as multiple distinct keys.

The ASCII Protocol Key Definition

According to the Memcached ASCII protocol specification, a key is defined as an arbitrary string of characters with two major restrictions: it cannot exceed 250 bytes in length, and it cannot contain control characters or whitespace (including spaces, tabs, and newline characters). Because the ASCII parser splits incoming command lines by space characters, any whitespace within a key fundamentally alters how the server reads the request.

Retrieval Commands: Accidental Multi-Get

When executing retrieval commands such as get or gets, the ASCII protocol supports querying multiple keys simultaneously by separating each key with a space:

get key1 key2 key3\r\n

If an application submits a single key containing a space, such as user profile, Memcached reads the space as a separator:

get user profile\r\n

Instead of querying a single item named "user profile", Memcached interprets this as a request for two separate items: one with the key "user" and one with the key "profile". If neither key exists independently, the server simply returns END. If one or both happen to exist, Memcached returns data for those unintended keys, potentially causing silent data mismatches or bugs in the application.

Storage Commands: Protocol Format Errors

Storage commands—including set, add, replace, append, and prepend—require a strict sequence of parameters:

<command> <key> <flags> <exptime> <bytes> [noreply]\r\n

If a key contains spaces, the positional parsing of these parameters breaks. For instance, sending:

set user profile 0 3600 5\r\n

causes Memcached to parse "user" as the key and "profile" as the <flags> parameter. Because <flags> must be an integer, the parser fails to convert the string to a numeric value.

When this happens, Memcached immediately rejects the command and replies with a client-side error:

CLIENT_ERROR bad command line format

The connection remains open, but the data is not stored.

How to Handle Keys Requiring Spaces

Applications that must map data to identifiers with spaces have several standard alternatives:

  1. Substitution: Replace spaces with safe separator characters such as underscores (_), colons (:), or hyphens (-) before issuing the command.
  2. Hashing: Pass keys through a hashing algorithm (such as SHA-256 or MD5) to produce fixed-length, alphanumeric strings that comply with Memcached key rules.
  3. Encoding: Use URL-encoding (percent-encoding) or Base64 encoding to convert whitespace into non-spaced ASCII characters.
