How to Secure Memcached UDP Endpoints

Exposing Memcached UDP endpoints to the public internet presents significant security risks, most notably leaving servers vulnerable to being weaponized in high-volume distributed denial-of-service (DDoS) amplification attacks. Because UDP is a connectionless protocol that does not validate source IP addresses, unauthenticated requests with spoofed IPs can trigger massive responses directed at targeted victims. This guide outlines the essential steps administrators must take to eliminate unauthenticated access to Memcached via UDP, including disabling UDP entirely, binding services to trusted local interfaces, implementing firewall restrictions, and verifying service isolation.

1. Disable UDP Support Entirely

Unless your infrastructure strictly requires UDP for Memcached traffic, the most effective mitigation is to disable UDP support altogether. In versions 1.5.6 and newer, UDP is disabled by default, but it may remain enabled on older deployments or due to legacy configuration templates.

To disable UDP:

  • Debian/Ubuntu (/etc/memcached.conf):
    Add the -U 0 parameter to the configuration file:

    -U 0

  • RHEL/CentOS/Rocky Linux (/etc/sysconfig/memcached):
    Append -U 0 to the OPTIONS directive:

    OPTIONS="-U 0 -l 127.0.0.1"

After updating the configuration, restart the service to apply the changes:

sudo systemctl restart memcached

2. Bind Memcached to Localhost or Private Networks

Memcached does not require exposure to the public internet. If the service must be accessed by application servers across a network, bind it exclusively to a private internal IP address or the loopback interface (127.0.0.1).

  • In /etc/memcached.conf, set the listen address:

    -l 127.0.0.1

    Or specify your internal interface IP:

    -l 10.0.0.10

Restart the service to ensure it ceases listening on 0.0.0.0 (all interfaces).

3. Implement Firewall Rules

Network-level access control provides an essential layer of defense against accidental misconfigurations. Configure host-based firewalls to drop unauthorized inbound traffic on port 11211.

  • Using iptables:

    # Drop all incoming UDP traffic on port 11211
sudo iptables -A INPUT -p udp --dport 11211 -j DROP

# Allow TCP traffic only from a trusted application server IP
sudo iptables -A INPUT -p tcp -s 10.0.0.5 --dport 11211 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 11211 -j DROP

  • Using ufw (Ubuntu):

    sudo ufw deny proto udp to any port 11211
sudo ufw allow proto tcp from 10.0.0.5 to any port 11211

  • Using firewalld (RHEL-based distributions):

    sudo firewall-cmd --permanent --remove-port=11211/udp
sudo firewall-cmd --permanent --zone=trusted --add-source=10.0.0.5/32
sudo firewall-cmd --reload

4. Enable SASL Authentication (For TCP)

Memcached supports Simple Authentication and Security Layer (SASL) to mandate credentials before processing commands. While SASL is designed for TCP and cannot natively secure unauthenticated stateless UDP packets, enabling it enforces authentication for your legitimate cached data access once UDP is disabled.

To enable SASL:

  1. Ensure the cyrus-sasl and cyrus-sasl-plain packages are installed.
  2. Add the -S flag to your Memcached configuration file.
  3. Configure your SASL credentials in /etc/sasl2/memcached.conf.

5. Verify Configuration and Port Status

Confirm that the UDP port is closed and that Memcached is only listening on the intended interfaces.

Check listening UDP ports using ss:

sudo ss -ulpn | grep 11211

If UDP has been disabled properly, this command should return no results.

To verify overall network exposure, inspect the listening sockets:

sudo ss -tlpn | grep 11211

Ensure the output displays 127.0.0.1:11211 or your designated private IP, rather than 0.0.0.0:11211 or :::11211.
