Understanding Memcached stats detail Output

The stats detail command in Memcached provides operational metrics broken down by key prefixes, enabling administrators to identify cache traffic patterns and optimize access keys. By turning on detailed statistics and dumping the results, Memcached outputs four primary operation counts for each prefix: get, hit, set, and del. This article breaks down each of these visible metrics, explains the output structure of the stats detail dump command, and outlines how to interpret the data.

Enabling and Accessing Detailed Stats

Memcached does not collect prefix statistics by default due to performance overhead. To view metrics, the feature must be enabled interactively via a Telnet or netcat session:

  1. stats detail on: Starts collecting prefix-level counters.
  2. stats detail dump: Displays the collected statistics.
  3. stats detail off: Stops collecting stats.

Output Format

When running stats detail dump, Memcached separates keys by a delimiter (by default, a colon :) and returns lines in the following format:

PREFIX <prefix_name> get <count> hit <count> set <count> del <count>

The output concludes with the line END.

Visible Metrics Breakdown

Every line in the stats detail dump output reports the following metrics for a specific prefix:

  • PREFIX <prefix_name>: Identifies the namespace or prefix segment of the key before the configured separator. If a key is user:1001, the prefix metric bucket will be user.
  • get: The cumulative number of get retrieval commands executed against keys matching this prefix.
  • hit: The cumulative number of get requests for this prefix that successfully located and returned an active item.
  • set: The total count of storage operations (such as set, add, or replace) executed for keys under this prefix.
  • del: The total number of delete commands executed for keys under this prefix.

Derived Insights

Using the visible metrics, you can calculate key performance indicators for each namespace:

  • Prefix Hit Rate: Calculated as hit / get. A low ratio indicates that keys in this prefix are frequently missing or expiring prematurely.
  • Read-to-Write Ratio: Calculated as get / set. This shows whether a namespace is read-heavy or write-heavy, helping you determine appropriate expiration times and eviction priorities.
