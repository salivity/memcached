How to Limit Memcached CPU Core Usage

This article outlines how to restrict the maximum CPU core usage of a Memcached process, covering both the native thread configuration settings within Memcached itself and external operating system controls used to bind or throttle an actively running instance.

Native Memcached Setting: The Thread Flag (-t)

Memcached does not feature an internal setting to throttle overall CPU percentage, but it natively controls core utilization through its thread allocation setting. By default, Memcached starts with 4 worker threads. Because each worker thread handles client connections concurrently, assigning fewer threads directly limits how many CPU cores Memcached can saturate simultaneously.

You can configure this using the -t or --threads parameter:

memcached -t 2

In standard Linux installations, this setting is managed via the configuration file (typically /etc/memcached.conf on Debian/Ubuntu or /etc/sysconfig/memcached on RHEL/CentOS):

  • Debian/Ubuntu (/etc/memcached.conf): Add or edit -t <number_of_threads>
  • RHEL/CentOS (/etc/sysconfig/memcached): Add -t <number_of_threads> to the OPTIONS string.

Limiting a Running Memcached Process via CPU Affinity (taskset)

To restrict an already running Memcached process to specific CPU cores without restarting it, assign its CPU affinity using taskset.

  1. Identify the Process ID (PID) of Memcached:

    pgrep memcached

  2. Pin the running process and all its lightweight threads to specific CPU cores (e.g., cores 0 and 1):

    taskset -a -cp 0,1 <PID>

The -a (or --all-tasks) flag is essential because it applies the affinity mask to all existing worker threads inside the running process.

Restricting CPU Usage via Systemd

If Memcached is managed by systemd, you can enforce hard CPU constraints directly in the service configuration. This persists across service restarts and provides deterministic core limits.

Create a drop-in systemd configuration file:

sudo systemctl edit memcached

Add the resource control directives under the [Service] block:

[Service]
# Restrict Memcached to specific CPU cores
AllowedCPUs=0,1

# Alternatively, cap total CPU time (e.g., 150% equals 1.5 full cores)
CPUQuota=150%

Apply the changes to the running service:

sudo systemctl daemon-reload
sudo systemctl restart memcached

Dynamic Throttling with cpulimit

To dynamically cap the CPU percentage of an active process without altering core affinity or restarting the daemon, use the cpulimit utility:

sudo cpulimit -p <PID> -l 100

The -l argument represents the total percentage across all cores (e.g., 100 limits execution to the equivalent of one full CPU core, while 200 limits it to two cores).
