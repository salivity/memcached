How to Log Admin Actions in Memcached

Memcached is designed for high-performance caching and minimizes internal overhead, which means it does not offer built-in, fine-grained audit logging by default. This guide explains how system operators can configure logging to record administrative actions—such as cache flushes, configuration inspects, and server terminations—by utilizing native verbosity flags, systemd service redirects, network proxies, and kernel-level auditing tools.

1. Enabling Native Verbosity Flags

Memcached provides built-in verbosity flags that output events to standard error (stderr). While not an enterprise audit trail, increasing verbosity captures operational events and client commands.

To adjust logging levels, update the Memcached configuration file (typically located at /etc/memcached.conf on Debian/Ubuntu or /etc/sysconfig/memcached on RHEL/CentOS):

  • -v: Logs basic events, including server startup, shutdown, and major warnings.
  • -vv: Logs client-issued commands, including administrative requests such as flush_all and stats, along with responses.
  • -vvv: Logs internal state transitions and full command lifecycles. (Not recommended in production due to substantial performance degradation).

For administrative auditing, configure -vv in your configuration file:

# /etc/memcached.conf
-vv
-s /var/run/memcached/memcached.sock
-u memcached

2. Capturing Output via Systemd and Syslog

Because Memcached writes its native logs to stderr, system operators must route this stream to persistent storage.

If running under systemd, log streams are automatically directed to systemd-journald. You can verify this by modifying the systemd override file:

sudo systemctl edit memcached

Add the following directives to guarantee that standard error is routed to the journal:

[Service]
StandardOutput=journal
StandardError=journal

Apply changes and restart the daemon:

sudo systemctl daemon-reload
sudo systemctl restart memcached

To extract administrative actions (such as cache purges) from the logs, query the journal:

journalctl -u memcached | grep -Ei "flush|stats"

3. Deploying Mcrouter for Audit Logging

Because running Memcached with -vv in high-throughput environments generates excessive I/O, using a caching proxy such as Facebook's Mcrouter is the standard approach for production-grade audit logging.

Place Mcrouter between the application and Memcached instances. Mcrouter can intercept incoming commands and log administrative actions selectively without enabling verbose logging on the storage nodes themselves.

  1. Route administrative traffic through the proxy layer.
  2. Configure Mcrouter’s logging targets to route mutating commands (such as flush_all) to a centralized logging system (e.g., Fluentd, Logstash, or rsyslog).

4. Logging Administrative Commands via eBPF or Auditd

To audit administrative actions without modifying Memcached configurations or impacting performance, operators can track socket interactions using Linux kernel auditing.

Using bpftrace or custom eBPF probes, operators can monitor payload data sent across TCP port 11211 to detect specific plain-text administrative commands:

# Monitor inbound 'flush_all' commands on the Memcached port
sudo bpftrace -e 'tracepoint:syscalls:sys_enter_recvfrom /args->addr->sa_data[0] == 0x2b/ { printf("%s\n", str(args->ubuf)); }'

Alternatively, use auditd to monitor the Memcached binary and its environment for modifications, signals, and termination actions:

sudo auditctl -w /usr/bin/memcached -p x -k memcached_execution
sudo auditctl -w /etc/memcached.conf -p wa -k memcached_config_change

All configuration edits and process terminations will now be logged in /var/log/audit/audit.log.
