How to Prevent Memcached DDoS Attacks

Memcached amplification attacks exploit publicly exposed, misconfigured Memcached servers to launch high-volume Distributed Denial of Service (DDoS) attacks using spoofed UDP traffic. This article outlines the essential security measures required to secure your Memcached instances, including disabling UDP support, binding the service strictly to local or private network interfaces, enforcing firewall rules, enabling authentication, and maintaining up-to-date software to prevent servers from being weaponized.

1. Disable UDP Support

The primary vector for Memcached DDoS amplification is the User Datagram Protocol (UDP), which allows attackers to spoof source IP addresses and amplify traffic volume by factors over 50,000. Memcached instances should have UDP disabled unless it is strictly required.

To disable UDP, add the -U 0 parameter to your Memcached configuration file (typically located at /etc/memcached.conf on Debian/Ubuntu or /etc/sysconfig/memcached on RHEL/CentOS):

-U 0

After updating the configuration, restart the Memcached service:

sudo systemctl restart memcached

2. Bind to Localhost or Private Interfaces

Memcached was never designed to face the public internet. By default, it should only listen on localhost (127.0.0.1) or an isolated internal network interface accessible only by your application servers.

Ensure the listening interface is set to 127.0.0.1 in the configuration file:

-l 127.0.0.1

If multiple application servers must access the instance, bind it strictly to a private, non-routable VPC subnet IP (e.g., 10.x.x.x or 192.168.x.x) rather than 0.0.0.0.

3. Implement Strict Firewall Rules

Configure host-based firewalls (such as ufw or iptables) and cloud security groups to drop all inbound traffic to Memcached’s default port (11211) from unauthorized sources.

To block public access while allowing access only from a specific application server using ufw:

sudo ufw deny 11211
sudo ufw allow from <APPLICATION_SERVER_IP> to any port 11211 proto tcp

Always ensure that UDP port 11211 is completely blocked from the internet.

4. Enable SASL Authentication

If your deployment requires network access across multiple hosts, enable Simple Authentication and Security Layer (SASL) support to mandate client authentication.

  1. Install the necessary SASL packages (sasl2-bin or cyrus-sasl).
  2. Add the -S flag to /etc/memcached.conf to enforce SASL.
  3. Create authorized credentials using saslpasswd2.

This prevents unauthorized actors from executing arbitrary commands or manipulating cache data.

5. Keep Memcached Updated

Ensure your server runs modern versions of Memcached. Since version 1.5.6, UDP is disabled by default out of the box. Regularly applying operating system and package updates ensures critical security patches are active.

6. Audit and Verify Exposure

After applying configurations, verify that your server does not expose port 11211 to the outside world. Test from an external machine using Nmap or Netcat:

nc -v -u -z <YOUR_SERVER_IP> 11211

If the port is unreachable or connection is refused, the instance is successfully protected from participating in amplification attacks.
