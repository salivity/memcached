Enable TLS Client Authentication in Memcached

Securing a Memcached deployment with mutual TLS (mTLS) prevents unauthorized data access by requiring clients to present a valid, trusted cryptographic certificate before executing cache commands. This guide outlines the essential steps to configure and verify TLS client certificate authentication in Memcached, covering certificate preparation, service configuration options, and connection testing using OpenSSL.

1. Verify TLS Support in Memcached

Memcached must be compiled with OpenSSL support. Verify that your installed binary supports TLS by checking its help output:

memcached -h | grep -i ssl

If the TLS options (such as -Z or --enable-ssl) are absent, you must build Memcached from source using the --enable-tls flag:

./configure --enable-tls
make
sudo make install

2. Prepare Certificates and Keys

Mutual TLS requires a Certificate Authority (CA), a server certificate and private key, and a client certificate and private key.

  1. Generate the CA key and certificate:

    openssl req -x509 -newkey rsa:4096 -nodes -keyout ca.key -out ca.crt -days 365 -subj "/CN=Memcached-CA"

  2. Generate and sign the server certificate:

    openssl req -newkey rsa:2048 -nodes -keyout server.key -out server.csr -subj "/CN=memcached-server"
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365

  3. Generate and sign the client certificate:

    openssl req -newkey rsa:2048 -nodes -keyout client.key -out client.csr -subj "/CN=memcached-client"
openssl x509 -req -in client.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out client.crt -days 365

Store the private keys in secure directories with restricted read permissions (e.g., chmod 600).

3. Configure Memcached for TLS Client Verification

Launch Memcached with TLS enabled, specifying the server certificate, private key, trusted CA certificate, and the verification mode.

Memcached uses OpenSSL's verification bitmask for ssl_verify_mode. To enforce client certificate authentication, set the mode to 3 (which combines SSL_VERIFY_PEER [1] and SSL_VERIFY_FAIL_IF_NO_PEER_CERT [2]):

memcached -Z \
  -o ssl_chain_cert=/path/to/server.crt \
  -o ssl_key=/path/to/server.key \
  -o ssl_ca_cert=/path/to/ca.crt \
  -o ssl_verify_mode=3 \
  -p 11211 \
  -u memcached

Configuration Parameters

  • -Z: Enables TLS mode.
  • ssl_chain_cert: Path to the server's certificate file (or certificate chain).
  • ssl_key: Path to the server's private key.
  • ssl_ca_cert: Path to the CA certificate used to validate connecting clients.
  • ssl_verify_mode=3: Enforces that clients must present a certificate signed by the specified CA; connections without a valid certificate are rejected.

4. Verify TLS Client Authentication

Use OpenSSL's s_client utility to verify both valid and invalid connection attempts.

Test a Valid Connection

Connect by providing the trusted client certificate and private key:

openssl s_client -connect 127.0.0.1:11211 \
  -cert client.crt \
  -key client.key \
  -CAfile ca.crt

Once the handshake completes and displays Verify return code: 0 (ok), type standard Memcached commands to test functionality:

version
VERSION 1.6.x
quit

Test Rejection Without a Client Certificate

Attempt to connect without presenting client credentials:

openssl s_client -connect 127.0.0.1:11211 -CAfile ca.crt

The TLS handshake should fail immediately, and the server will terminate the connection with an alert such as sslv3 alert handshake failure or peer did not return a certificate.

Test Rejection With an Untrusted Certificate

Generate a self-signed certificate not issued by ca.crt:

openssl req -x509 -newkey rsa:2048 -nodes -keyout rogue.key -out rogue.crt -days 1 -subj "/CN=rogue"

Attempt the connection using the untrusted certificate:

openssl s_client -connect 127.0.0.1:11211 \
  -cert rogue.crt \
  -key rogue.key \
  -CAfile ca.crt

The connection will be rejected during the TLS handshake with an unknown ca or certificate verify failed error, confirming that strict client verification is operational.
