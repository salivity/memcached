Disable Protocols and Commands in Memcached

This article covers the configuration parameters used to restrict network protocols and disable specific commands within Memcached. By adjusting these startup options, administrators can reduce the attack surface of a Memcached instance, prevent cache-clearing accidents, and ensure only authorized communication protocols are active.

Disabling UDP

Memcached listens on both TCP and UDP by default in older versions, which historically exposed instances to UDP amplification denial-of-service (DDoS) attacks. You can disable the UDP protocol entirely by setting the UDP port to 0.

  • CLI flag: -U 0

  • Configuration file (/etc/memcached.conf):

    -U 0

Disabling TCP (Enforcing Unix Domain Sockets)

If Memcached is running on the same host as the client application, network protocols can be disabled in favor of local Unix domain sockets. This eliminates network exposure entirely.

To disable the TCP listener, specify TCP port 0 and define a socket path using -s.

  • CLI flags: -p 0 -s /var/run/memcached/memcached.sock -a 0760

  • Configuration file:

    -p 0
-s /var/run/memcached/memcached.sock
-a 0760

Restricting the Communication Protocol (ASCII vs. Binary)

Memcached supports an ASCII text protocol, a legacy binary protocol, and modern meta commands. You can restrict the server to accept only a designated protocol using the -B (or --protocol) option, rather than allowing automatic detection.

  • Accept only ASCII:

    -B ascii

    This setting prevents clients from utilizing the binary protocol.

  • Accept only Binary:

    -B binary

    This setting disables ASCII parsing and requires clients to use the binary protocol.

  • Automatic negotiation (Default):

    -B auto

Note: The binary protocol is deprecated in modern Memcached versions in favor of the enhanced ASCII meta commands (ms, mg, md, mn), but the option remains for backward compatibility.

Disabling the flush_all Command

The flush_all command invalidates all existing items in the cache simultaneously. Because accidental execution or malicious injection of this command can lead to severe cache stampedes on backend databases, Memcached provides an option to disable it.

  • CLI flag: -o no_flush

  • Configuration file:

    -o no_flush

When this flag is active, calls to flush_all will return an error or be ignored depending on the client protocol in use.

Restricting Dangerous Commands via Authentication

While individual commands outside of flush_all cannot be selectively removed via dedicated configuration flags, you can restrict the execution of all commands by enabling SASL authentication. This requires clients to authenticate before any storage or retrieval command sets can be executed.

  • CLI flag: -S (requires Memcached to be built with --enable-sasl)

  • Configuration file:

    -S

When -S is set, unauthenticated requests are rejected, effectively shutting off all standard command sets to unauthenticated users.
