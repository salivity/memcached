Unix Domain Sockets vs TCP for Local Memcached

Connecting to a local Memcached instance via Unix domain sockets (UDS) instead of TCP loopback (127.0.0.1) provides substantial performance, security, and resource management benefits. This article outlines the core advantages of Unix domain sockets for local inter-process communication, explaining how bypassing the network stack reduces latency, lowers CPU overhead, enhances security, and prevents port exhaustion under high loads.

Reduced Latency and Higher Throughput

Unix domain sockets operate directly within the operating system kernel, copying data straight between processes using memory buffers. In contrast, TCP sockets—even when bound to the localhost loopback interface—must route packets through the complete network stack.

By eliminating the network layer, Unix domain sockets bypass:

  • IP encapsulation and decapsulation
  • Packet segmentation and reassembly
  • Checksum calculations
  • TCP acknowledgments, window management, and congestion control algorithms

This direct data transfer yields noticeably lower latency per request and higher overall read/write throughput, which is critical for cache-heavy workloads where operations occur in sub-millisecond intervals.

Lower CPU Utilization

Because the operating system does not execute the TCP/IP stack logic for every cache operation, CPU utilization drops significantly. Processing network frames and managing TCP state machines consumes processor cycles that could otherwise be utilized by your application. On servers handling thousands of concurrent queries per second, switching to domain sockets can free up substantial CPU capacity.

Prevention of Ephemeral Port Exhaustion

Under heavy traffic, applications that open and close local TCP connections to Memcached can rapidly exhaust the system's ephemeral port range. Sockets frequently linger in the TIME_WAIT state to ensure late packets are handled correctly, leading to socket starvation and connection timeouts.

Unix domain sockets do not use network ports or IP addresses; they are represented as nodes on the filesystem. Consequently, they are entirely immune to port exhaustion and TIME_WAIT saturation, making high-concurrency environments far more resilient.

Enhanced Security via Filesystem Permissions

A TCP socket bound to 127.0.0.1 is accessible to any user or process with network permissions on the host machine. Unless Memcached is configured with SASL authentication, any compromised process running locally can interact with the cache.

Unix domain sockets leverage standard POSIX filesystem permissions (ownership, group, and chmod bits). Access to the Memcached socket can be restricted exclusively to the system users or groups that require it (e.g., the web server or application user). This integration simplifies least-privilege security models without requiring application-level authentication overhead.

Implementation Simplicity

Memcached natively supports Unix domain sockets via command-line flags. Launching the daemon with the -s /path/to/memcached.sock parameter specifies the socket path, and the -a flag sets the appropriate file permissions (e.g., -a 0660). Most modern client libraries (such as PHP-Memcached, Python's pymemcache, and Node.js clients) allow developers to connect simply by providing the file path instead of a host and port combination.
