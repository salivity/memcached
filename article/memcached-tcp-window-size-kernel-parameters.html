Memcached TCP Window Size Kernel Parameters

Optimizing the operating system kernel's TCP window parameters is critical for maximizing Memcached throughput and minimizing latency. This guide covers the essential Linux kernel settings required to tune TCP read and write buffers, avoid socket buffer exhaustion during high concurrency, and ensure efficient data transfer over modern high-bandwidth networks.

Why TCP Window Sizing Matters for Memcached

Memcached handles massive volumes of small-to-medium network packets, often interspersed with large multi-key fetches. If the TCP window size—dictated by the OS receive and send buffers—is too small, network interfaces stall waiting for ACKs (acknowledgments), throttling throughput. Conversely, if the windows are too large across tens of thousands of idle connections, system memory is wasted.

Tuning these parameters aligns the socket buffers with the Bandwidth-Delay Product (BDP) of your network while keeping memory usage under control.

Recommended Kernel Parameters

Add or update the following parameters in /etc/sysctl.conf or a dedicated /etc/sysctl.d/99-memcached.conf file:

1. Enable TCP Window Scaling

TCP window scaling is required to support window sizes greater than 64 KB, which is essential for high-throughput connections.

net.ipv4.tcp_window_scaling = 1

2. Maximum Core Socket Buffers

These parameters set the hard ceiling for OS-level socket buffer allocations across all protocols.

net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
  • Recommended value: 16777216 (16 MB) is suitable for 10 GbE networks. For 25 GbE or 40 GbE networks, increase this to 33554432 (32 MB).

3. Default Core Socket Buffers

These settings define the initial buffer allocation for sockets before TCP autotuning overrides them.

net.core.rmem_default = 262144
net.core.wmem_default = 262144
  • Recommended value: 262144 (256 KB) ensures connections begin with sufficient buffer space for rapid burst handling.

4. TCP Read and Write Buffer Autotuning

The Linux kernel uses dynamic buffer autotuning defined by three values: min, default, and max (in bytes).

net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216
  • Min (4096): The minimum buffer size allocated per socket under low memory conditions.
  • Default (87380 / 65536): The initial receive/send buffer allocated to new connections.
  • Max (16777216): The upper ceiling to which the TCP window can dynamically expand. This must match or be lower than net.core.rmem_max and net.core.wmem_max.

Supporting Connection Parameters

To prevent buffer queue drops when clients aggressively connect to Memcached, align the network backlog parameters with your window settings:

net.core.somaxconn = 65535
net.core.netdev_max_backlog = 10000
  • net.core.somaxconn: Increases the socket listen backlog ceiling from the standard default (often 128 or 1024) to handle bursts of concurrent connection requests.
  • net.core.netdev_max_backlog: Increases the maximum number of packets queued on the input interface before processing.

Applying the Changes

To load the updated kernel parameters immediately without rebooting, run:

sudo sysctl -p /etc/sysctl.d/99-memcached.conf

Verify that the changes are active using:

sysctl net.ipv4.tcp_rmem net.ipv4.tcp_wmem net.core.rmem_max net.core.wmem_max

Memory Considerations

When configuring these maximums, calculate the worst-case memory consumption: Max Connections × (tcp_rmem[max] + tcp_wmem[max]). If Memcached maintains 10,000 persistent connections, dynamically scaling all sockets to maximum capacity can consume significant system RAM. Ensure your server has sufficient RAM to avoid triggering the kernel's Out-Of-Memory (OOM) killer.
