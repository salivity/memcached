Optimize Socket Buffers for Memcached Throughput

Optimizing network socket buffer sizes is essential for maximizing Memcached throughput, reducing latency spikes, and preventing packet loss under high-concurrency workloads. This guide outlines how TCP receive and send buffers affect Memcached performance, details the Linux kernel parameters required to scale socket memory, and explains how to align the operating system's network stack with Memcached's high-frequency, low-latency traffic patterns.

The Role of Socket Buffers in Memcached

Memcached relies on rapid, non-blocking I/O to handle thousands of concurrent requests per second. When clients send read and write requests faster than the operating system or Memcached can process them, incoming data queues in the kernel's socket receive buffer (SO_RCVBUF). Similarly, outgoing responses queue in the send buffer (SO_SNDBUF).

If these buffers are too small:

  • The TCP receive window shrinks to zero (zero-window condition), forcing the client to throttle transmission.
  • Incoming packets are dropped at the kernel level, triggering expensive TCP retransmissions and latency spikes.

If buffers are excessively large:

  • Kernel memory exhaustion occurs because pinned RAM is wasted across thousands of idle or low-traffic connections.

Calculating the Optimal Buffer Size

Buffer sizes should match the Bandwidth-Delay Product (BDP) of your network path:

\[\text{BDP} = \text{Bandwidth (bytes/sec)} \times \text{Round-Trip Time (sec)}\]

For a 10 Gbps network with a 0.5 ms round-trip time: \[\text{BDP} = (10 \times 10^9 \text{ bits/sec} / 8) \times 0.0005 \text{ sec} = 625,000 \text{ bytes} \approx 625 \text{ KB}\]

For peak throughput, the maximum TCP window size must be at least equal to the BDP. Adding a 20–30% safety margin accommodates buffer management overhead.

Tuning Linux Kernel Parameters

Memcached relies on the Linux networking stack for socket management. You must increase the system-wide limits and configure TCP window autotuning via /etc/sysctl.conf.

1. Core Socket Memory Limits

Set the maximum and default buffer sizes the kernel can allocate to any socket:

# Maximum receive socket buffer size (e.g., 16 MB)
net.core.rmem_max = 16777216

# Maximum send socket buffer size (e.g., 16 MB)
net.core.wmem_max = 16777216

# Default receive socket buffer size (e.g., 1 MB)
net.core.rmem_default = 1048576

# Default send socket buffer size (e.g., 1 MB)
net.core.wmem_default = 1048576

2. TCP Autotuning Vector

Modern Linux kernels dynamically scale buffer sizes per connection. The tcp_rmem and tcp_wmem parameters accept three values: min, default, and max.

# TCP receive buffer: min (4 KB), default (1 MB), max (16 MB)
net.ipv4.tcp_rmem = 4096 1048576 16777216

# TCP send buffer: min (4 KB), default (1 MB), max (16 MB)
net.ipv4.tcp_wmem = 4096 1048576 16777216

Enable dynamic window scaling:

net.ipv4.tcp_window_scaling = 1

Apply these changes immediately:

sudo sysctl -p

Memcached Configuration Adjustments

Alongside socket buffers, tune Memcached’s connection handling to prevent queue exhaustion:

  • Listen Backlog (-b): The default backlog for pending connections can cause connection drops during burst traffic. Increase the backlog queue size to match high-concurrency environments:

    memcached -b 4096

    Ensure the OS allows this by setting net.core.somaxconn = 4096 in /etc/sysctl.conf.

  • Thread Count (-t): Ensure you have sufficient threads to drain the socket buffers quickly. A standard configuration is matching the number of physical CPU cores (typically up to 8–16 threads, after which lock contention can degrade performance).

NIC Ring Buffers and Driver Offloads

Small socket buffers are only one potential bottleneck. If the Network Interface Card (NIC) ring buffers overflow, packets are dropped before reaching socket memory.

Inspect and max out the NIC ring buffers using ethtool:

# View current and maximum ring buffer sizes
ethtool -g eth0

# Set RX and TX ring buffers to maximum (e.g., 4096)
sudo ethtool -G eth0 rx 4096 tx 4096

Verification and Monitoring

After applying changes, monitor the network stack under real production load to ensure socket buffers are behaving as intended.

Check for socket buffer overflows and dropped packets:

# Check for TCP listen queue overflows and drops
netstat -s | grep -i "buffer errors\|overflowed\|listen drops"

Inspect active socket buffers and window sizes for Memcached (port 11211):

ss -ntia '( dport = :11211 or sport = :11211 )'

Look at the rcv_space, snd_wnd, and cwnd parameters. If rcv_space consistently hits the configured max value while drop counters increase, incrementally scale net.core.rmem_max and the upper value of net.ipv4.tcp_rmem until drops cease.
