Linux Kernel Tuning for High-Concurrency Memcached

High-concurrency Memcached deployments require underlying Linux kernel tuning to handle tens of thousands of simultaneous TCP connections without dropping packets or exhausting system resources. This article outlines the essential kernel and system parameters—spanning file descriptor limits, socket queues, TCP memory buffers, and virtual memory behavior—necessary to eliminate network bottlenecks and achieve maximum throughput on dedicated Memcached servers.

File Descriptor Limits

Every active client connection to Memcached consumes a file descriptor. The default Linux limit (usually 1024) will quickly cause "Too many open files" errors during traffic spikes.

System-Wide Limit

Increase the system-wide maximum file allocation in /etc/sysctl.conf:

fs.file-max = 2097152

Process Limit

Ensure the user running Memcached (typically memcached) has sufficient limits defined in /etc/security/limits.conf:

memcached soft nofile 1048576
memcached hard nofile 1048576

If running under systemd, set LimitNOFILE=1048576 inside the service unit file (/etc/systemd/system/memcached.service.d/override.conf).

Connection Backlog and Queue Depths

When hundreds of clients connect simultaneously, connection requests can be dropped before Memcached can accept them if the backlog queues are too small.

Listen Backlog (net.core.somaxconn)

This setting caps the maximum queue length of completely established sockets waiting to be accepted:

net.core.somaxconn = 65535

Note: Ensure the Memcached -b (backlog) startup parameter matches or exceeds this value.

SYN Backlog (net.ipv4.tcp_max_syn_backlog)

Determines the maximum number of half-open connections (SYN received, but ACK not yet received) the kernel will queue:

net.ipv4.tcp_max_syn_backlog = 65535

Network Device Backlog (net.core.netdev_max_backlog)

Defines the maximum number of packets queued on the input side when the network interface receives packets faster than the kernel can process them:

net.core.netdev_max_backlog = 10000

Ephemeral Ports and TCP Recycling

In environments where clients frequently open and close connections instead of using persistent pools, port exhaustion and sockets stuck in the TIME_WAIT state can degrade performance.

Ephemeral Port Range (net.ipv4.ip_local_port_range)

Expand the range of available local ports:

net.ipv4.ip_local_port_range = 1024 65535

Reusing Sockets (net.ipv4.tcp_tw_reuse)

Allow the kernel to safely reuse TIME_WAIT sockets for new outgoing connections when protocol-safe:

net.ipv4.tcp_tw_reuse = 1

Maximum TIME_WAIT Sockets (net.ipv4.tcp_max_tw_buckets)

Prevents simple denial-of-service or memory consumption by capping total TIME_WAIT sockets:

net.ipv4.tcp_max_tw_buckets = 1440000

TCP Buffer Sizes and Memory Allocation

Proper TCP buffer sizing prevents dropped packets while avoiding unbounded RAM consumption per connection.

# Maximum socket receive and send buffer sizes
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216

# Default socket receive and send buffer sizes
net.core.rmem_default = 262144
net.core.wmem_default = 262144

# Min, default, and max TCP buffer sizes (in bytes)
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216

Virtual Memory and Paging

Memcached relies on deterministic in-memory key-value lookups. Any disk swapping introduces massive latency spikes that render high-concurrency caching ineffective.

Disable Swapping (vm.swappiness)

Configure the kernel to avoid swapping application memory to disk:

vm.swappiness = 0

Setting vm.swappiness = 0 aggressively prevents the kernel from swapping process memory, ensuring Memcached stays entirely within physical RAM. Alternatively, start Memcached with the -k flag to lock all memory pages via mlockall.

Applying Kernel Changes

To apply these parameters immediately without a reboot, place them in /etc/sysctl.d/99-memcached.conf and run:

sysctl --system
